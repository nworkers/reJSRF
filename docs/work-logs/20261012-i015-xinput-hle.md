# Issue #15 작업 로그 — XInput HLE

작업 지시: [20261012-i015](../work-orders/20261012-i015-xinput-hle.md) · 설계: [20261012-i015](../design/20261012-i015-xinput-hle.md)

## 요약

XAPI의 장치·입력 함수 11개를 HLE로 바꿨다(함수 단위 HLE 선택, XDK 변수 바인딩, SDL3 게임패드·키보드 입력 계약). 부팅은 `IoCreateDevice`를 더 이상 만나지 않고, 입력 초기화, 폰트 텍스처, 셰이더·버퍼 생성을 지나 **`DirectSoundCreate`가 MCPX APU 레지스터를 읽는 곳**까지 간다. 그 과정에서 세 가지 문제를 찾아 고쳤다.

1. **장치 도착 시점.** 게임의 DirectInput식 열거는 `XInitDevices` 직후 게임패드가 "변경 대기"로 보이면 `E_FAIL`을 돌려주고, 그 실패가 그래픽·입력 객체 생성 전체를 실패시킨다. `XGetDevices`/`XGetDeviceChanges`를 원본과 같은 구조체 의미로 HLE에 옮기고, 게임패드는 첫 조회 뒤에 도착하게 했다.
2. **xboxrecomp 디스어셈블러 버그.** vtable로만 도달하는 별칭 본문(`0x00154D70`)의 분기 대상 `0x00154DAA`가 어떤 본문에도 속하지 않아 `g_esp += 4`만 하는 미해결 스텁이 되었고, 원래 `ret 0xc`인 블록이 실행되지 않아 스택이 12바이트 어긋났다. 이 어긋남이 lift된 호출자들로 전파되어 생성 함수가 결과를 엉뚱한 슬롯에 썼다. 포크에서 고치고 업스트림 PR [sp00nznet/xboxrecomp#199](https://github.com/sp00nznet/xboxrecomp/pull/199)로 보냈다. 미해결 스텁은 184개에서 109개로 줄었다.
3. **커널 HLE의 `RootDirectory` 의사 핸들.** XAPI는 `D:\…`를 `ObDosDevicesDirectory()`(`0xFFFFFFFD`) 기준으로 연다. 커널 HLE가 이를 `\??\`로 해석하게 해 폰트 파일이 열린다.

## 과정

1. `regenerate.py`에 함수 단위 선택(`hle_libraries.json`의 `functions`)과 XDK 변수 표(`rexbox_xdk_variables[]`)를 넣었다. 타이틀 프로파일의 `BindTitleHle`가 표를 `HleRegistry::BindVariable`로 등록한다(43개).
2. lift 본문으로 `XPP_DEVICE_TYPE`(`{현재, 변경, 이전}`)과 `XGetDevices`/`XGetDeviceChanges`의 의미, `XInputGetState`의 보고서 길이(게임패드 18바이트)를 확인했다.
3. 첫 부팅: `XInitDevices`를 지났지만 null 객체 vtable 호출이 건너뛰어졌다. 호출 지점을 경고에 넣고(`returns to …`), 비정상 정지·건너뛴 호출 시 메모리 덤프(`REXBOX_STOP_DUMP`, `REXBOX_SKIP_DUMP`), 직접 호출 프로파일에 esp와 호출 지점을 기록하는 진단을 더해, 원인 1(열거 실패)을 찾았다.
4. 원인 1을 고치자 다음 null 호출에서 `esi`가 반환 주소였다. 생성 코드의 `RECOMP_ABI_CHECK` 모드를 CMake 옵션 `REJSRF_RECOMP_ABI_CHECK`로 켜고 보고 함수를 구현해, 반환 주소조차 pop하지 않은 첫 호출 `0x00154E00` → `vtable+0x1C`(`0x00154D70`) → 스텁 `sub_00154DAA`를 찾았다. 원인 2.
5. 원인 2를 고친 뒤 폰트 열기 실패(`C000003A`)로 null 호출이 하나 더 남아 원인 3을 고쳤다. 건너뛴 간접 호출은 0건.
6. re2DJ의 SDL3 게임패드 리더는 디지털 버튼만 다뤄 코드를 가져오지 않았다(구조만 참고).

# Issue #15 work log — XInput HLE

Work order: [20261012-i015](../work-orders/20261012-i015-xinput-hle.md) · Design: [20261012-i015](../design/20261012-i015-xinput-hle.md)

## Summary

Eleven XAPI device and input functions now run on HLE (per-function HLE selection, XDK variable binding, an SDL3 gamepad and keyboard input contract). Boot no longer meets `IoCreateDevice`; it passes input initialization, the font texture and shader and buffer creation, and reaches **`DirectSoundCreate` reading MCPX APU registers**. Three problems were found and fixed on the way.

1. **Device arrival timing.** The game's DirectInput-style enumeration returns `E_FAIL` when the gamepad shows as a pending change right after `XInitDevices`, which failed the creation of its whole graphics and input object. `XGetDevices`/`XGetDeviceChanges` moved to HLE with the original's structure semantics, and the gamepad arrives after the first query.
2. **An xboxrecomp disassembler bug.** A branch target (`0x00154DAA`) of an alias body reached only through a vtable (`0x00154D70`) belonged to no body and became an unresolved stub doing only `g_esp += 4`; the block, which ends in `ret 0xc`, never ran and the stack came back 12 bytes off. The imbalance travelled through the lifted callers until a constructor stored its result in the wrong slot. Fixed on the fork and submitted upstream as [sp00nznet/xboxrecomp#199](https://github.com/sp00nznet/xboxrecomp/pull/199); unresolved stubs went from 184 to 109.
3. **The kernel HLE's `RootDirectory` pseudo-handles.** XAPI opens `D:\…` relative to `ObDosDevicesDirectory()` (`0xFFFFFFFD`); the kernel HLE now reads it as `\??\`, and the font file opens.

## Process

1. `regenerate.py` gained per-function selection (`functions` in `hle_libraries.json`) and the XDK variable table (`rexbox_xdk_variables[]`); the title profile's `BindTitleHle` registers the table with `HleRegistry::BindVariable` (43 variables).
2. The lifted bodies confirmed `XPP_DEVICE_TYPE` (`{current, change, previous}`), the semantics of `XGetDevices`/`XGetDeviceChanges` and `XInputGetState`'s report length (18 bytes for a gamepad).
3. First boot: past `XInitDevices`, but a null object's vtable call was skipped. The call site was added to the warning (`returns to …`), plus memory dumps at an abnormal stop or skipped call (`REXBOX_STOP_DUMP`, `REXBOX_SKIP_DUMP`) and esp and call site in the direct-call profile, which found cause 1 (the failing enumeration).
4. With cause 1 fixed, the next null call had a return address in `esi`. The generated code's `RECOMP_ABI_CHECK` mode, enabled through the new CMake option `REJSRF_RECOMP_ABI_CHECK` with a reporting function, named the first call that did not even pop its return address: `0x00154E00` → `vtable+0x1C` (`0x00154D70`) → stub `sub_00154DAA`. Cause 2.
5. After cause 2, one more null call remained from a failed font open (`C000003A`): cause 3. No indirect call is skipped now.
6. re2DJ's SDL3 gamepad reader handles digital buttons only, so no code was taken (its structure was a reference).

## Verification

The table in the Korean section applies: Debug and Release builds with zero warnings on our targets; kernel probe 28/28 (new: opening `D:\probe.bin` relative to `ObDosDevicesDirectory()`); decomp check 6/6; d3d8 check 13,557/0; `check_hle_pops.py` 0 mismatches (the 11 XInput exports included); xboxrecomp's pytest on the fork's `rejsrf` branch passing (with the new `test_alias_branch_orphans.py`, 4 cases, and `test_xadd_flags.py`); a `REJSRF_RECOMP_ABI_CHECK` boot with no missing-pop violations (known `_chkstk`-style helpers excluded); boot with no skipped indirect calls, faulting on APU `0xFE801100` in `DirectSoundCreate`.
