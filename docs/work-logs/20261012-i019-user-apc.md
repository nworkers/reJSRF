# Issue #19 작업 로그 — 커널 HLE 사용자 APC

작업 지시: [20261012-i019](../work-orders/20261012-i019-user-apc.md) · 설계: [20261012-i019](../design/20261012-i019-user-apc.md)

## 요약

커널 HLE에 사용자 APC를 넣었다. 스레드별 큐, 파일 I/O 완료 루틴 큐잉, 경고 가능 사용자 모드 대기 5종의 전달과 `STATUS_USER_APC`, `NtUserIoApcDispatcher`(ordinal 232)다. 부팅은 `dsstdfx.bin` 읽기 대기를 지나 **효과 이미지 다운로드(효과 20개), 스트리밍 PCM 버퍼 4개, 첫 `D3DDevice_Swap`, 폰트 읽기, 효과음 버퍼 10개, 세이브 메타데이터 확인**까지 간다. 약 50초 뒤 thread 2가 `D3DVertexBuffer_Lock` 다음에 `0x0FE80026`을 읽다 fault한다.

1. **XAPI의 모양.** `ReadFileEx`(`0x00146375`)는 `NtReadFile`의 `ApcRoutine`에 커널 import 232를, `ApcContext`에 완료 루틴을, `IoStatusBlock`에 `OVERLAPPED`를 넘기고, 오류 상태면 `FALSE`를 돌려준다. 그래서 오류로 끝난 I/O는 APC를 넣지 않는다.
2. **전달 순서.** 신호된 객체가 먼저, 그다음 대기 중 APC. 실행은 잠금 없이 `CallGuest`로 한다. 루틴이 커널 thunk 주소면 실행기가 레지스트리로 HLE를 찾는다.
3. **놓친 함수 하나 더.** 첫 프레임 뒤 vtable 슬롯 `0x0007BE30`이 건너뛰어졌다. 앞 함수의 switch 표를 선형 스윕이 코드로 읽어 seed가 "명령 중간"으로 거부된 경우였고, 실행에서 닿은 주소이므로 xboxrecomp의 `observed` seed로 넣었다.

## 과정

1. 게임이 import하는 APC·대기 커널 함수를 확인했다. `NtQueueApcThread`, `KeInsertQueueApc`는 import하지 않아 범위에서 뺐다.
2. `kernel_apc.cpp`(큐, 전달, `NtUserIoApcDispatcher`, 게스트 스레드가 아닐 때의 `thread_local` 기록), 파일 I/O의 공용 `CompleteIo`, `WaitForObjects`의 APC 확인과 `WaitAndDeliver`, 경고 가능 `KeDelayExecutionThread`, 공용 `NtStatusToDosError`를 넣었다.
3. 커널 probe의 가짜 실행기 `CallGuest`가 레지스트리에 바인딩된 주소를 실행하게 하고, probe 완료 루틴을 export로 바인딩해 APC 검사 14개를 더했다(42개).
4. 부팅 1: 효과 이미지, 버퍼 4개, 첫 프레임까지 갔고 `0x0007BE30` 간접 호출 하나가 건너뛰어졌다. 재생성 로그의 "Rejected 3 seed(s) landing inside an already-decoded instruction"과 디스어셈블로 원인(앞 함수 `sub_0007BDD0`의 점프 표 0x7BE08, 색인 표 0x7BE10, nop 패딩 뒤 SEH 프롤로그)을 확인했다. `0x0001FD10`, `0x00020F10`도 같은 모양이다.
5. 부팅 2: 건너뛴 간접 호출 0건. 폰트(`Z:` 캐시 없음 → `D:`), 효과음 ADPCM 버퍼, `SaveMeta.xbx` 확인 뒤 fault. 마지막 간접 호출은 getter `0x00038ED0`(`[ecx+0x1770]`, 0 반환)이다.

# Issue #19 work log — kernel HLE user APCs

Work order: [20261012-i019](../work-orders/20261012-i019-user-apc.md) · Design: [20261012-i019](../design/20261012-i019-user-apc.md)

## Summary

The kernel HLE now has user APCs: a per-thread queue, queuing of file I/O completion routines, delivery with `STATUS_USER_APC` in the five alertable user-mode waits, and `NtUserIoApcDispatcher` (ordinal 232). Boot passes the wait for the `dsstdfx.bin` read and reaches **the effects image download (20 effects), four streaming PCM buffers, the first `D3DDevice_Swap`, font loading, ten sound-effect buffers and the save-metadata check**; after about 50 s, thread 2 faults reading `0x0FE80026` after `D3DVertexBuffer_Lock`.

1. **XAPI's shape.** `ReadFileEx` (`0x00146375`) passes kernel import 232 as `NtReadFile`'s `ApcRoutine`, the completion routine as `ApcContext` and the `OVERLAPPED` as `IoStatusBlock`, and returns `FALSE` on an error status, so I/O that ends in an error queues no APC.
2. **Delivery order.** A signalled object first, then pending APCs. They run without the lock through `CallGuest`; when the routine is a kernel thunk address, the executor finds the HLE through the registry.
3. **One more missed function.** After the first frame the vtable slot `0x0007BE30` was skipped: the linear sweep had decoded the previous function's switch tables as code, so its seed was rejected as mid-instruction. The address was reached at run time, so it is now an xboxrecomp `observed` seed.

## Process

1. Checked which APC and wait kernel functions the game imports; it imports neither `NtQueueApcThread` nor `KeInsertQueueApc`, which stay out of scope.
2. Added `kernel_apc.cpp` (the queue, delivery, `NtUserIoApcDispatcher`, a `thread_local` record outside guest threads), a shared `CompleteIo` for file I/O, the APC check in `WaitForObjects` with `WaitAndDeliver`, an alertable `KeDelayExecutionThread`, and a shared `NtStatusToDosError`.
3. The kernel probe's fake executor now runs `CallGuest` for addresses bound in the registry, and a probe completion routine bound as an export backs 14 new APC checks (42 in all).
4. Boot 1: reached the effects image, four buffers and the first frame, with one indirect call to `0x0007BE30` skipped. The regeneration log's "Rejected 3 seed(s) landing inside an already-decoded instruction" and the disassembly showed why (the previous function `sub_0007BDD0`'s jump table at 0x7BE08 and index table at 0x7BE10, nop padding, then an SEH prologue); `0x0001FD10` and `0x00020F10` have the same shape.
5. Boot 2: no skipped indirect calls; fonts (no `Z:` cache, so `D:`), the sound-effect ADPCM buffers and the `SaveMeta.xbx` check, then the fault. The last indirect call is the getter `0x00038ED0` (`[ecx+0x1770]`, returning 0).

## Verification

The table in the Korean section applies: Debug and Release builds with zero warnings on our targets; kernel probe 42/42 (14 new APC checks) and DSOUND probe 48/48 in both configurations; decomp check 6/6; d3d8 check 13,557/0; `check_hle_pops.py` 0 mismatches; a headless boot with `REXBOX_AUDIO=none` with no skipped indirect calls, past the effects image, 14 buffers, the first frame and fonts, faulting at `0x0FE80026` after about 50 s.

## Remaining

* Next task: the fault (the caller of the `0x00038ED0` getter and where `esi = 0x0FE80022` comes from). It follows `D3DVertexBuffer_Lock`, so the D3D8 HLE's buffer lock results or object fields are the first suspects.
* See the sound-effect buffers' `SetBufferData` and the first `Play` in a run (hearing sound).
* Disassembler: functions after switch tables are rejected as mid-instruction seeds, which also covers the two remaining candidates (`0x0001FD10`, `0x00020F10`); consider an xboxrecomp fix that realigns the sweep at the end of a table of known size.
* `NtQueueApcThread` and kernel APCs when the game imports them.
