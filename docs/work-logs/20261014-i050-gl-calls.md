# Issue #50 작업 로그 — 그리기마다의 GL 호출 줄이기

작업 지시: [20261014-i050](../work-orders/20261014-i050-gl-calls.md) · 설계: [20261014-i050](../design/20261014-i050-gl-calls.md)

## 요약

GL 호출을 세는 진단(`REXBOX_GL_CALLS`)을 더했다. 데모 프레임은 그리기 483개에 GL을 10,505번 부르고 있었다.

세 가지를 고쳤다.
* 정점 속성 끄기·켜기와 포인터 지정을 바뀐 것만 보낸다.
* 프레임버퍼는 바뀔 때만 다시 묶는다.
* 정점 상수는 location run마다 한 번에 보낸다.

결과:
* 호출은 프레임당 4,123번으로 61% 줄었다.
* Intel HD 620에서 present 스레드 CPU 시간이 약 5% 줄었다.
* 렌더링은 기준 덤프와 같다.

## 과정

1. **계수 래퍼**: 로더의 `Load(&f.X, "glX")` 80줄을 `Load<__LINE__>`로 바꿨다. 줄마다 다른 템플릿 인스턴스가 드라이버 포인터를 저장하고 호출 수를 센다(`REXBOX_GL_CALLS=1`일 때만).
2. **재생성**: 서브모듈이 다른 작업(#48)에서 `c345158`로 바뀌어 있었다. 생성 코드 해시가 달라 configure가 멈췄고, 다시 생성했다(약 23분, 빌드 포함).
3. **기준 측정**(설계 §1): 10,505번/프레임. 속성 끄기 3,694, 켜기·포인터 각 1,534, `glBindBuffer` 911, `glUniform4fv` 861, `glBindFramebuffer` 487이었다.
4. **속성 캐시와 프레임버퍼**:
   * 호출이 4,817번이 됐다(속성 끄기·켜기 각 56, `glBindFramebuffer`는 상위 16개에서 빠짐).
   * 기준과 번갈아 3회 재니 present 스레드 CPU가 약 6% 줄었다. 483 그리기 구간 23.54 → 22.08 ms, 372 그리기 구간 23.34 → 22.05 ms.
   * 이때 기계가 느린 상태여서 이전 측정보다 값이 크다.
5. **상수 호출**: 임시 계측(커밋하지 않음)으로 `glUniform4fv`가 모두 `c[]`의 run 갱신임을 확인했다. 프레임당 831번, 레지스터 3,482개였다.
   * location run마다 한 번에 보내게 바꿨다. `glUniform4fv`는 160번이 됐고, 전체 호출은 4,123번이 됐다.
   * uniform buffer로 바꿔도 더 줄지 않아 하지 않았다(설계 §2.4).
6. **화면**: 프레임 2,800~3,400 덤프는 v0.0.15 덤프와는 달랐지만, i042 실행의 덤프와는 다른 픽셀이 0개였다.
   * 데모가 진행 타이밍에 따라 두 가지 카메라 위치 중 하나로 가는 것과 맞다(frame-time §5).
   * 렌더링 차이는 없다.
7. **최종 측정**: 기준과 번갈아 3회 쟀다. 기계 상태가 회차마다 크게 흔들려 회차별로 짝지어 보면, w10~w12 9쌍의 합이 174.95 → 165.46 ms(-5.4%)였다.

# Issue #50 work log — fewer GL calls per draw

Work order: [20261014-i050](../work-orders/20261014-i050-gl-calls.md) · Design: [20261014-i050](../design/20261014-i050-gl-calls.md)

## Summary

A diagnostic now counts GL calls (`REXBOX_GL_CALLS`). The demo frame was making 10,505 GL calls for 483 draws.

Three things changed:
* Vertex attributes are enabled, disabled and pointed only where they change.
* The framebuffer is bound only when it changes.
* Vertex constants go in one call per location run.

Results:
* Calls fell by 61%, to 4,123 per frame.
* The presenting thread's CPU time fell by about 5% on an Intel HD 620.
* Rendering matches a reference dump.

## Process

1. **Counting wrappers**: the loader's 80 `Load(&f.X, "glX")` lines became `Load<__LINE__>`. Each line instantiates its own template, which keeps the driver pointer and counts calls (only with `REXBOX_GL_CALLS=1`).
2. **Regeneration**: the submodule had moved to `c345158` in other work (#48), so the generated-code hash differed and configure stopped. The code was regenerated (about 23 minutes with the build).
3. **Baseline** (design §1): 10,505 calls per frame. Attribute disables were 3,694, enables and pointers 1,534 each, `glBindBuffer` 911, `glUniform4fv` 861, `glBindFramebuffer` 487.
4. **Attribute cache and framebuffer**:
   * Calls fell to 4,817 (attribute enables and disables 56 each; `glBindFramebuffer` left the top 16).
   * Three alternating runs against the baseline showed presenting-thread CPU about 6% lower: 23.54 → 22.08 ms in the 483-draw window, 23.34 → 22.05 ms in the 372-draw window.
   * The machine was in a slow state then, hence the higher values than earlier.
5. **Constant calls**: a temporary counter (not committed) showed every `glUniform4fv` was a run update of `c[]`, 831 calls and 3,482 registers per frame.
   * Sending each location run in one call left 160 `glUniform4fv` and 4,123 calls in all.
   * A uniform buffer would not cut further and was not done (design §2.4).
6. **Picture**: dumps of frames 2,800–3,400 differed from the v0.0.15 dumps but matched the i042 run's dumps with 0 pixels different.
   * That fits the demo reaching one of two camera positions depending on timing (frame-time §5).
   * There is no rendering difference.
7. **Final measurement**: three runs alternating with the baseline. The machine state varied strongly between rounds, so rounds were paired: the sum of nine w10–w12 pairs went from 174.95 to 165.46 ms (-5.4%).

## Measurements and verification

The tables in the Korean section apply:

* calls in the 483-draw window: 10,505 → 4,123 per frame
* demo frames: 0 pixels different from the i042 reference
* presenting-thread CPU: about -5%
* Debug and Release builds with zero warnings
* regression tools in both configurations: kernel 56/56, D3D8 116/116, DSOUND 48/48, d3d8 check 14,018/0, decomp check 6/0

## Remaining

* A VAO per range would cut `glVertexAttribPointer` (1,446) and `glBindBuffer` (912) (design §2.4).
* Stutter from compiling shaders on first use is #51.
