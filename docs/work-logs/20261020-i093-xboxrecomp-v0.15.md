# 작업 로그: xboxrecomp v0.15.0 전환 (issue #93)

설계: [20261020-i093](../design/20261020-i093-xboxrecomp-v0.15.md) · 작업 지시: [20261020-i093](../work-orders/20261020-i093-xboxrecomp-v0.15.md)

## 1. 검토

* v0.15.0(`6376eb8`)의 `tools.disasm`을 임시 worktree에서 같은 XBE·seed로 돌려 현재 핀과 비교했다. 113개 메서드 중 10개만 항목, 데모 정지 주소 3개 없음. 즉 v0.14.0의 보류 사유가 그대로다.
* `_pass_data_ptr_targets`에 계측을 넣어 107개의 거절 사유를 한 번에 기록했다(간접 꼬리 89, 표 arm 밖 9, 직접 분기 밖 8, funclet 1). 상세는 [function-discovery](../analysis/function-discovery.md).
* 시험 패치 세 번(설계 4.4). 두 번째·세 번째에서 바이트 인덱스 표가 항목으로 들어오는 오탐(`0xEC090`, `0xFFB60`, `0x11A1DC`)을 찾아 거절 규칙을 넣었다. 최종 111/113, 데모 주소 4/4, upstream pytest 전부 통과.

## 2. xboxrecomp fork

* `fix/table-entry-shapes`(v0.15.0 위 세 커밋 `adc827c`, `4953472`, `3a1afff`, 합성 테스트 13개). 각 테스트는 v0.15.0에서 실패하고 해당 커밋에서 통과하는 것을 확인했다. `PYTHONUTF8=1 pytest tools/disasm tools/recomp`: 721 passed, 111 skipped.
  * 첫 커밋의 `allow_indirect_tails="mem"`는 처음엔 메모리 피연산자만 받았다. JSRF `0x52010`·`0x52050`·`0x52090`(`mov eax,[eax*4+T]; …; jmp eax`)이 빠져서, 본문이 직접 적재한 레지스터도 받도록 고치고 테스트를 더했다.
  * JSRF 재확인: 항목 9,481개, trial 3과 시작·끝이 모두 같다.
* upstream PR [#236](https://github.com/sp00nznet/xboxrecomp/pull/236).
* `rejsrf-v0.15`(`5aae5df`) = 위 세 커밋 + `perf/mem-base-local` + `perf/xmm-intrinsics`(2) + `fix/fp-cc-cast` + 스텁 보고 재작성. PR #200 계열 6개 커밋은 얹어도 출력이 완전히 같아(9,478 항목 동일) 뺐다. 이전 핀은 `rejsrf-v0.13`(`1991221`).
* 스텁 보고 재작성(`5aae5df`): 생성된 스텁 파일 안에서 `RECOMP_UNRESOLVED_STUB(va)`를 정의하고 upstream의 `RECOMP_STUB_HIT`가 먼저 부른다. 런타임 헤더는 건드리지 않아 upstream `test_stub_log.py`가 그대로 통과한다.

## 3. reJSRF

* `recomp_abi.c`: `g_eflags` TLS 정의, 스레드 리셋 `0x202`.
* `recomp_bridge.cpp`: `xbox_PortIn`(읽기 0, `0x80C0`는 읽을 때마다 비트 5 토글), `xbox_PortOut`(무시). 포트별 첫 접근을 `BridgeFirstTimeAt`로 한 번 보고. 첫 빌드에서 문자열 리터럴의 `\n`이 실제 줄바꿈으로 들어가 C2001이 났고 고쳤다.
* submodule → `rejsrf-v0.15` `5aae5df`. 재생성: 함수 9,526(수동 223 포함), 미해결 스텁 74 → 28, `RECOMP_UNIMPL`에서 `in`·`out`·`popfd` 사라짐. disasm 300 s, lift 83 s.
* `find_pointer_targets.py`가 `0x30800`(.data `0x22BBF8` 참조, alias `0x307A0` 안), `0x129180`, `0x17E580`을 보고해 `--write`로 seed에 넣고 다시 생성했다. 그러자 alias였던 `0x307A0`(.data `0x1EC288` 참조)이 사라지고 공통 에필로그 스텁 `0x30849`가 생겨, `0x307A0`도 seed에 넣고 한 번 더 생성했다(seed 166개). 최종: 함수·alias 9,481, lift 9,526(수동 223 포함), 미해결 스텁 28, 후보 0.
* 처음 찍은 프레임은 전부 달랐는데, 새 exe가 빌드 폴더의 `rejsrf.ini`(`VBlankWait = false`, `RenderScale = 4`)를 읽어 게임이 최대 속도로 돈 탓이었다. 설정 없는 폴더에서 다시 찍었다.
* 문서: THIRD_PARTY_NOTICES, ARCHITECTURE, external-references, function-discovery(새), unresolved-stubs §4.

# Work log: moving to xboxrecomp v0.15.0 (issue #93)

Design: [20261020-i093](../design/20261020-i093-xboxrecomp-v0.15.md) · Work order: [20261020-i093](../work-orders/20261020-i093-xboxrecomp-v0.15.md)

## 1. Review

* v0.15.0's (`6376eb8`) `tools.disasm` was run in a scratch worktree on the same XBE and seeds and compared with the current pin: only 10 of the 113 methods are entries and the three demo stop addresses are absent, so v0.14.0's hold stands.
* Instrumenting `_pass_data_ptr_targets` recorded the refusal reason for 107 addresses in one run (indirect tail 89, table arm outside the gap 9, direct branch outside 8, funclet 1). Details in [function-discovery](../analysis/function-discovery.md).
* Three trial patches (design 4.4). The second and third caught byte index tables arriving as entries (`0xEC090`, `0xFFB60`, `0x11A1DC`) and added the refusals. Final: 111 of 113, 4 of 4 demo addresses, the whole upstream pytest suite green.

## 2. The xboxrecomp fork

* `fix/table-entry-shapes` (three commits on v0.15.0, `adc827c`, `4953472`, `3a1afff`, 13 synthetic tests). Each test fails on v0.15.0 and passes with its commit. `PYTHONUTF8=1 pytest tools/disasm tools/recomp`: 721 passed, 111 skipped.
  * The first commit's `allow_indirect_tails="mem"` first took memory operands only; JSRF's `0x52010`, `0x52050` and `0x52090` (`mov eax,[eax*4+T]; …; jmp eax`) dropped out, so a register the body itself loaded is taken too, with a test.
  * JSRF re-check: 9,481 entries, same starts and ends as trial 3.
* Upstream PR [#236](https://github.com/sp00nznet/xboxrecomp/pull/236).
* `rejsrf-v0.15` (`5aae5df`) = those three + `perf/mem-base-local` + `perf/xmm-intrinsics` (2) + `fix/fp-cc-cast` + the stub-report rewrite. The six PR #200 commits change nothing on top (9,478 identical entries) and are dropped. The previous pin stays on `rejsrf-v0.13` (`1991221`).
* Stub-report rewrite (`5aae5df`): the generated stub file defines `RECOMP_UNRESOLVED_STUB(va)` and upstream's `RECOMP_STUB_HIT` calls it first. The runtime header is untouched, so upstream's `test_stub_log.py` still passes.

## 3. reJSRF

* `recomp_abi.c`: `g_eflags` TLS definition, thread reset `0x202`.
* `recomp_bridge.cpp`: `xbox_PortIn` (reads 0; `0x80C0` toggles bit 5 per read), `xbox_PortOut` (ignored); the first access per port reported once through `BridgeFirstTimeAt`. The first build failed with C2001 because the `\n` of the log strings had become real line breaks; fixed.
* Submodule → `rejsrf-v0.15` `5aae5df`. Regeneration: 9,526 functions (223 manual), unresolved stubs 74 → 28, `in`, `out` and `popfd` gone from `RECOMP_UNIMPL`. disasm 300 s, lift 83 s.
* `find_pointer_targets.py` reported `0x30800` (referenced from .data `0x22BBF8`, inside alias `0x307A0`), `0x129180` and `0x17E580`; `--write` put them in the seeds and the code was regenerated. That made the alias `0x307A0` (referenced from .data `0x1EC288`) disappear and a shared-epilogue stub `0x30849` appear, so `0x307A0` was seeded too and the code regenerated once more (166 seeds). Final: 9,481 functions and aliases, lift 9,526 (223 manual), 28 unresolved stubs, 0 candidates left.
* The first frame capture differed everywhere because the new exe read the build folder's `rejsrf.ini` (`VBlankWait = false`, `RenderScale = 4`) and the game ran as fast as it could. It was captured again from a folder without settings.
* Documents: THIRD_PARTY_NOTICES, ARCHITECTURE, external-references, function-discovery (new), unresolved-stubs §4.
