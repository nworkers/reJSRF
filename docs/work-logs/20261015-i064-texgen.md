# Issue #64 작업 로그 — 텍스처 좌표 생성과 텍스처 변환

작업 지시: [20261015-i064](../work-orders/20261015-i064-texgen.md) · 설계: [20261015-i064](../design/20261015-i064-texgen.md)

## 요약

고정 기능 정점 처리에서 텍스처 좌표를 스테이지별로 정점 셰이더에서 만든다. 먼저 생성하고(카메라 공간 법선·위치·반사 벡터) 이어서 변환한다(`COUNTn`, `PROJECTED`). 데모의 법선 환경 맵, 캐릭터 명암 램프, 스크롤 텍스처가 적용되어 `texgen`·`texture transform`이 미구현 보고에서 사라졌다.

## 과정

1. **추적**(임시 코드, 커밋하지 않음): `BuildKey`에서 생성·변환을 쓰는 스테이지의 상태와 행렬을 프레임 2,800·3,100에 기록했다(설계 §1의 표).
   * 스크롤 행렬의 이동량이 셋째 행에 있었다. 그래서 변환할 때 2D 세트를 `(u, v, 1, 0)`으로 채우는 D3D 규약을 따랐다.
2. **구현**:
   * 키에 스테이지별 `tex_gen`·`tex_transform`과 `stage_coords`·`has_normal`·`normalize_normals`를 더했다. 고정 기능 정점 셰이더는 스테이지마다 `v_tex<s>`를 쓴다.
   * 정점 프로그램 경로(`stage_coords` 거짓)는 바꾸지 않았다.
   * 법선 행렬(3×3 역전치)은 CPU에서 여인수로 계산한다(`NormalMatrix`).
   * `rexbox_d3d8_probe`에 12개 검사를 더했다(135 → 147).
3. **화면**: 같은 장면의 i062 빌드 프레임(3,200)과 비교했다.
   * 주인공의 노란 바지·신발과 재킷에 명암 띠가 생겼다. 이전에는 평평한 색이었다.
   * 행인에게도 밝고 어두운 면이 나뉘어 보인다.
4. **성능**: 이전 빌드(main)와 번갈아 세 번씩 실행해 데모 구간(창 9~12)의 CPU 열을 비교했다. 결과는 아래 표에 있다.

# Issue #64 work log: texture coordinate generation and texture transforms

Work order: [20261015-i064](../work-orders/20261015-i064-texgen.md) · Design: [20261015-i064](../design/20261015-i064-texgen.md)

## Summary

With fixed-function vertex processing, the vertex shader now makes each stage's texture coordinates. It first generates them (camera-space normal, position or reflection vector), then transforms them (`COUNTn`, `PROJECTED`). The demo's normal-based environment maps, the characters' shading ramp and the scrolling textures now apply, and `texgen` and `texture transform` are gone from the unimplemented report.

## Steps

1. **Trace** (temporary code, not committed): `BuildKey` logged the state and matrices of the stages using generation or transforms at frames 2,800 and 3,100 (the table in design §1).
   * The scrolling matrices keep their translation in the third row, so transformed 2D sets follow D3D's `(u, v, 1, 0)` padding.
2. **Implementation**:
   * The key gained per-stage `tex_gen` and `tex_transform`, plus `stage_coords`, `has_normal` and `normalize_normals`. The fixed-function vertex shader writes `v_tex<s>` per stage.
   * The vertex-program path (`stage_coords` false) is unchanged.
   * The normal matrix (the 3×3 inverse transpose) is computed on the CPU from cofactors (`NormalMatrix`).
   * 12 checks in `rexbox_d3d8_probe` (135 → 147).
3. **Picture**, compared with the i062 build's frame of the same scene (3,200):
   * The main character's yellow trousers, shoes and jacket now show shading bands; they were flat before.
   * The pedestrians show lit and dark sides too.
4. **Performance**: the previous build (main) and this one ran alternately, three times each, comparing the CPU column over the demo windows (9–12). The results are in the table below.
