# 작업 로그: xboxrecomp v0.16.0, Debug에서만 스텁 보고 (issue #115)

설계: [20261023-i115](../design/20261023-i115-xboxrecomp-v0.16.md) · 작업 지시: [20261023-i115](../work-orders/20261023-i115-xboxrecomp-v0.16.md)

## 한 일

1. 검토(설계 §2)
   * upstream은 v0.16.0이다. #93의 disasm 수정 셋이 PR #236으로 들어갔다.
   * fork 전용 커밋 다섯 개를 v0.16.0 위에 올리는 시험은 충돌이 없었고, ABI 헤더도 같았다.
   * 디스어셈블 단계를 비교해 함수 경계 변화를 쟀다.
2. 범위(사용자 결정): fork `rejsrf`에 v0.16.0을 병합하고 `5aae5df`(스텁 보고)를 되돌린다. 스텁 보고는 upstream의 `RECOMP_STUB_LOG`로 하고, Debug 빌드에서만 앱이 넣는다.
3. fork(`nworkers/xboxrecomp`)
   * `rejsrf`에 `v0.16.0`을 병합했다(`4ab8e289`). #236 커밋이 같아 충돌이 없었다.
   * `5aae5df`를 되돌렸다(`6acdc0c9`).
   * v0.16.0과 다른 곳은 `recomp_types.h`(XMM, C4310), `translator.py`의 메모리 기준값 4줄, 그 테스트뿐이다.
   * upstream 테스트 794개 통과(`PYTHONUTF8=1`, `tools/fusion` 제외). SSH remote `fork`로 fast-forward push했다(force 아님).
   * 이전 핀은 `rejsrf-v0.15`(`5aae5df`)에 남아 있다.
4. reJSRF
   * `third_party/xboxrecomp`를 `6acdc0c9`로 올렸다.
   * `src/app/main.cpp`의 `EnableStubLogInDebug()`: Debug 빌드에서 `RECOMP_STUB_LOG`가 없으면 게스트 진입 전에 `1`로 넣고(Windows `_putenv_s`, 그 밖 `setenv`) 한 줄을 알린다. 사용자가 준 값은 그대로다.
5. 두 변형을 다시 생성했다.
6. 문서: 분석 `unresolved-stubs.md`(§1 보고 방식, §5), `function-discovery.md`(표, §3a), 가이드, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md`, `docs/kb/external-references.md`.

# Work log: xboxrecomp v0.16.0, stub logging in Debug only (issue #115)

Design: [20261023-i115](../design/20261023-i115-xboxrecomp-v0.16.md) · Work order: [20261023-i115](../work-orders/20261023-i115-xboxrecomp-v0.16.md)

## Done

1. Review (design §2)
   * upstream is at v0.16.0, with #93's three disasm fixes in it as PR #236.
   * A trial put the five fork-only commits onto v0.16.0 without conflicts, with the same ABI header.
   * A disassembly-stage comparison measured how the function boundaries move.
2. Scope (the user's decision): merge v0.16.0 into the fork's `rejsrf` and revert `5aae5df` (the stub report); stub reporting uses upstream's `RECOMP_STUB_LOG`, which the app sets in Debug builds only.
3. Fork (`nworkers/xboxrecomp`)
   * `v0.16.0` merged into `rejsrf` (`4ab8e289`); #236's commits are the same, so there were no conflicts.
   * `5aae5df` reverted (`6acdc0c9`).
   * Against v0.16.0 only `recomp_types.h` (XMM, C4310), the four memory-base lines in `translator.py` and their tests differ.
   * 794 upstream tests pass (`PYTHONUTF8=1`, without `tools/fusion`). Pushed fast-forward (no force) with the SSH remote `fork`.
   * The previous pin stays on `rejsrf-v0.15` (`5aae5df`).
4. reJSRF
   * `third_party/xboxrecomp` moved to `6acdc0c9`.
   * `EnableStubLogInDebug()` in `src/app/main.cpp`: in Debug builds, when `RECOMP_STUB_LOG` is not set, it sets it to `1` before the guest entry (`_putenv_s` on Windows, `setenv` elsewhere) and says so in one line; a value the user set stays.
5. Both variants were regenerated.
6. Documents: analysis `unresolved-stubs.md` (§1 reporting, §5), `function-discovery.md` (table, §3a), the guide, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md`, `docs/kb/external-references.md`.
