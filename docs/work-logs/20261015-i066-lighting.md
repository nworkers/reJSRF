# Issue #66 작업 로그 — 고정 기능 조명

작업 지시: [20261015-i066](../work-orders/20261015-i066-lighting.md) · 설계: [20261015-i066](../design/20261015-i066-lighting.md)

## 요약

`SetLight`·`LightEnable`·`SetMaterial`이 광원과 재질을 저장한다. 고정 기능 정점 셰이더는 D3D 조명식을 계산한다(주변광, 방향·점·스폿 광원의 확산과 정반사, 재질 색 원천). 데모의 조명 그리기는 결과가 흰색이라 화면은 그대로이고, 미구현 보고는 하나도 남지 않았다.

## 과정

1. **상태 저장**: `PipelineState`에 `lights`와 `material`을 더했다. `LightEnable`은 `d3d8_device`의 받기만 하는 함수에서 `d3d8_state`로 옮겼다.
2. **추적**(임시 코드, 커밋하지 않음): 프레임 150마다 조명 그리기의 광원·재질·렌더 상태 92~106을 기록했다(설계 §1의 표).
   * 방향광 하나, 정점 색 없는 형식, `AMBIENT` 흰색, 재질 확산·주변광 1이다. 조명 결과는 흰색으로 잘린다.
   * FVF `0x1118`이 XYZB2라 정점 블렌딩도 확인했다. `VERTEXBLEND`(118)가 0이라 가중치는 쓰이지 않는다(WORLD1의 첫 행과 이동도 단위 행렬과 같았다). 지금처럼 무시하는 것이 맞다.
3. **구현**:
   * 키: 켜진 광원 종류(최대 8), 색 원천 4개(정점 형식에 대해 해석), 로컬 뷰어
   * 광원별로 펼친 GLSL. 광원 위치·방향은 CPU에서 View로 옮긴다.
   * `rexbox_d3d8_probe`에 11개 검사를 더했다(147 → 158).
4. **화면**:
   * 3,200 프레임의 주인공은 i064 빌드와 같은 모습이다.
   * 4,650 프레임의 조명 그리기(셀 셰이딩 캐릭터와 외곽선)도 정상이다.
   * 셰이더 컴파일 오류는 없다.

## 남은 것

* 비방향 광원의 정반사 시점 방향(`LOCALVIEWER` 거짓일 때 (0, 0, −1))과, N·L ≤ 0에서 정반사를 빼는 처리는 **추정**이다. 게임은 정반사를 끄고 방향광만 쓰므로 데모에서는 확인되지 않는다.
* `TWOSIDEDLIGHTING`, 뒷면 재질(96~99, 104), 정점 블렌딩(`VERTEXBLEND` ≠ 0)은 다루지 않는다. 게임이 켜지 않았다.
* D3D8 미구현 보고는 기본 데모 구간에서 없다. 안개·bump·`CopyRects`·큐브 맵은 데모 구간에서 나오지 않았고, 플레이 중에는 나올 수 있다.

# Issue #66 work log: fixed-function lighting

Work order: [20261015-i066](../work-orders/20261015-i066-lighting.md) · Design: [20261015-i066](../design/20261015-i066-lighting.md)

## Summary

`SetLight`, `LightEnable` and `SetMaterial` keep the lights and the material. The fixed-function vertex shader computes D3D's lighting equation: ambient, diffuse and specular from directional, point and spot lights, and the material color sources. The demo's lit draws come out white, so the picture is unchanged, and no unimplemented report is left.

## Steps

1. **State**: `PipelineState` gained `lights` and `material`. `LightEnable` moved from an accept-only function in `d3d8_device` to `d3d8_state`.
2. **Trace** (temporary code, not committed): every 150 frames, the lit draws' lights, material and render states 92–106 were logged (the table in design §1).
   * One directional light, formats without vertex color, a white `AMBIENT`, material diffuse and ambient 1: the lit result clamps to white.
   * FVF `0x1118` is XYZB2, so vertex blending was checked too. `VERTEXBLEND` (118) is 0, so the weights are unused (WORLD1's first row and translation matched the identity, too), and ignoring them is right.
3. **Implementation**:
   * Key: the enabled light types (up to 8), the four color sources (resolved against the vertex format), the local viewer.
   * GLSL unrolled per light. Light positions and directions are moved to camera space by View on the CPU.
   * 11 checks in `rexbox_d3d8_probe` (147 → 158).
4. **Picture**:
   * The main character at frame 3,200 looks as in the i064 build.
   * The lit draws at frame 4,650 (cel-shaded characters with outlines) look right.
   * No shader compile errors.

## Left open

* Two details are **inferred**: the viewer direction for specular without `LOCALVIEWER`, (0, 0, −1), and dropping specular where N·L ≤ 0. The game turns specular off and uses only a directional light, so the demo cannot confirm them.
* `TWOSIDEDLIGHTING`, back materials (96–99, 104) and vertex blending (`VERTEXBLEND` ≠ 0) are not handled; the game does not turn them on.
* The default demo window reports no unimplemented D3D8 path now. Fog, bump, `CopyRects` and cube maps did not appear there, but may in play.
