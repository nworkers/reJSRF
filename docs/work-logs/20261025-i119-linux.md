# 작업 로그: Linux x64 / x86 앱 (issue #119)

설계: [20261025-i119](../design/20261025-i119-linux.md) · 작업 지시: [20261025-i119](../work-orders/20261025-i119-linux.md)

환경: WSL2 Ubuntu 24.04, GCC 13.3, CMake 3.28, Ninja. 소스는 `/mnt/e/…`(Windows 디스크), 게임 데이터와 `gen/`은 Windows와 공유.

## 한 일

1. **시험**(코드 수정 없이): x64·x86 Release가 빌드되고 데모가 Windows와 같은 파일 열기 순서로 돈다(설계 §2).
2. **rexbox 경고 2개**: rexbox issue #29 → [PR #30](https://github.com/reexec/rexbox/pull/30) → **v0.0.13**(`5582630`). DPC trace 문자열의 마지막 글자가 잘리던 버그(버퍼 16 → 24바이트)와 XbSymbolDatabase 헤더의 쓰이지 않는 표 경고.
3. **생성 코드 없는 트리의 링크 실패**(이 작업의 첫 CI 실행이 잡음): CI에는 `gen/`이 없어 rexbox가 레지스터 접근 함수 대체 라이브러리(`recomp_abi_none.c`)를 링크하는데, 그것이 이를 쓰는 `rexbox_recomp`보다 링크 줄에서 앞에 놓여 GNU ld가 미정의 참조 17개를 냈다(MSVC는 순서를 가리지 않아 v0.0.12에서 드러나지 않았음). 로컬 Linux 트리는 모두 `gen/`이 있어 시험에서 놓쳤다. rexbox issue #31 → [PR #32](https://github.com/reexec/rexbox/pull/32) → **v0.0.14**(`befa752`): 생성 코드 없는 분기에서 `rexbox_recomp`가 `<target>_abi`에 의존하게 했다. submodule을 v0.0.14로 올렸다.
4. **빌드 진입점**: `CMakePresets.json`(`linux-{x64,x86}-{debug,release}[-jp]`, Linux 호스트에서만 보임), `scripts/build_linux.sh <arch> <config> [us|jp] [--no-test] [--target …]`.
5. **재생성**: `regenerate.py`의 `symbol_tool_candidates()`가 자기 호스트의 빌드만 본다. WSL에서는 Windows 빌드 폴더도 보이므로, 전에는 첫 후보인 Windows `.exe`를 집어 interop으로 실행했고 그 프로그램이 `/mnt/…` 경로를 열지 못해 "not an XBE"로 실패했다.
6. **CI**: `linux` 작업(x64·x86 × debug·release; 패키지, `build_linux.sh`와 ctest, 앱 smoke, x64 release에서 일본판 앱 빌드와 smoke).
7. **문서**: 가이드 `linux-setup-and-build.md`(새), `README.md` 플랫폼 상태, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md`(rexbox v0.0.14).

# Work log: the Linux x64 / x86 app (issue #119)

Design: [20261025-i119](../design/20261025-i119-linux.md) · Work order: [20261025-i119](../work-orders/20261025-i119-linux.md)

Environment: WSL2 Ubuntu 24.04, GCC 13.3, CMake 3.28, Ninja; sources on `/mnt/e/…` (the Windows disk), game data and `gen/` shared with Windows.

## Done

1. **Trial** (no code changed): x64 and x86 Release build, and the demo runs with the same file-open sequence as Windows (design §2).
2. **The two rexbox warnings**: rexbox issue #29 → [PR #30](https://github.com/reexec/rexbox/pull/30) → **v0.0.13** (`5582630`): the DPC trace string lost its last character (buffer 16 → 24 bytes), and XbSymbolDatabase's header defines an unused table.
3. **A link failure in a tree without generated code** (caught by this task's first CI run): CI has no `gen/`, so rexbox links the accessor stand-in (`recomp_abi_none.c`), which came before its user `rexbox_recomp` on the link line; GNU ld reported 17 undefined references (MSVC ignores order, so v0.0.12 never showed it). Every local Linux tree had `gen/`, so the trial missed it. rexbox issue #31 → [PR #32](https://github.com/reexec/rexbox/pull/32) → **v0.0.14** (`befa752`): the no-generated-code branch makes `rexbox_recomp` depend on `<target>_abi`. The submodule moved to v0.0.14.
4. **Build entry**: `CMakePresets.json` (`linux-{x64,x86}-{debug,release}[-jp]`, visible on Linux hosts only) and `scripts/build_linux.sh <arch> <config> [us|jp] [--no-test] [--target …]`.
5. **Regeneration**: `regenerate.py`'s `symbol_tool_candidates()` looks only at this host's builds. On WSL the Windows build folder is visible too, so the first candidate, the Windows `.exe`, was picked and run through interop; it could not open `/mnt/…` paths and failed with "not an XBE".
6. **CI**: a `linux` job (x64 and x86 × debug and release: packages, `build_linux.sh` with ctest, the app smoke checks, and on x64 release the Japanese app build and smoke).
7. **Documents**: the new guide `linux-setup-and-build.md`, `README.md` platform status, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md` (rexbox v0.0.14).
