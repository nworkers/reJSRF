# Issue #3 작업 로그 — 커널 HLE 최소 구현

작업 지시: [20261012-i003](../work-orders/20261012-i003-kernel-hle.md) · 설계: [20261012-i003](../design/20261012-i003-kernel-hle.md)

## 요약

커널 export 103개를 구현해(import 120개 중 106개 바인딩) US 빌드가 `PsCreateSystemThreadEx`를 지나 게임 메인 스레드로 들어가게 했다. 메인 스레드는 XAPI 초기화를 끝까지 마친다. TLS, 크리티컬 섹션, 이벤트, `T:`·`U:` 드라이브, 캐시 드라이브 설정 섹터, `Z:` 파티션 포맷과 마운트가 모두 원본 순서대로 지나간 뒤, **D3D8 초기화가 NV2A 레지스터 `0xFD001804`를 읽는 지점**에서 멈춘다. 이것은 커널 밖 하드웨어 경계이고, 다음 task(D3D8 HLE)의 출발점이다. HLE 모듈은 런타임의 새 계약(`GuestCpu`, `GuestExecutor`, `Environment`, `HleCall`, `GuestHeap`)만 쓰고 lifter ABI는 모른다. 커널 단위 시험 27개가 게임 데이터 없이 통과하며 CI에 들어갔다.

## 과정

1. 진입점을 디스어셈블해 시작 순서를 확인했다(설계 §2). `fs:[0x28]`, `fs:[0x20]`, `fs:[4]`, `KTHREAD+0x28`, `ETHREAD+0x12C`의 쓰임과 음수 TLS index에서 "StackBase = TlsData + TlsDataSize"를 끌어냈다. xboxrecomp는 이 구조를 고정 주소의 가짜 블록으로 흉내 내지만, 우리는 스레드마다 실제 배치대로 만들었다.
2. 런타임 계약을 만들었다. 커널이 게스트 콜백을 불러야 하는 경우(`KeSynchronizeExecution`)가 있어 `GuestExecutor::CallGuest`를 추가했다.
3. 스레드 종료는 SEH로 네이티브 스택을 푸는데, MSVC 기본 `/EHsc`에서는 이때 C++ 소멸자가 실행되지 않는다. 그래서 `/EHa`로 바꿨다.
4. 첫 실행 frontier는 `NtOpenFile`이었다. 파일 계층(VFS + 서비스)을 넣자 XAPI가 `T:`·`U:`를 만들고, `\Device\Harddisk0\Partition0`을 열지 못해 `HalReturnToFirmware`로 갔다.
5. Partition0을 원시 장치로 열게 하고 IOCTL을 기록해 실제 요청 순서를 봤다. 캐시 설정 섹터(오프셋 0x800) 읽기·쓰기, Partition5 형상·파티션 정보, 원시 포맷 쓰기, `FSCTL_DISMOUNT_VOLUME`, `Z:` 연결 순이었다. 파티션 루트를 볼륨 객체(원시 쓰기 수용·폐기)로 열게 해서 통과시켰다.
6. 간접 호출 10개가 "대상 없음"으로 건너뛰어지는 것을 발견했다(`0x0018AFB0`–`0x0018C3C0`). disasm seed 파일 경로(`src/game/jsrf/recomp/*.json`)를 `regenerate.py`에 추가해 해결했다(함수 8,716 → 8,721개).
7. fault 보고를 "host − base mod 2³²"의 게스트 주소로 고쳐, Win32에서 wrap된 접근이 `0xFD001804`(NV2A MMIO)임을 드러냈다.
8. 시행착오: Python 일괄 치환 중 C 문자열의 `\n`, `\D`, `\r`, `\b`, `\t`가 제어 문자로 바뀌는 일이 여러 번 있었다. 모두 찾아 고쳤고, 이후 역슬래시가 들어가는 수정은 Edit 도구로만 했다.

# Issue #3 work log — minimal kernel HLE

Work order: [20261012-i003](../work-orders/20261012-i003-kernel-hle.md) · Design: [20261012-i003](../design/20261012-i003-kernel-hle.md)

## Summary

103 kernel exports (106 of the 120 imports bound) take the US build past `PsCreateSystemThreadEx` into the game's main thread. That thread completes XAPI initialization: TLS, critical sections, events, the `T:` and `U:` drives, the cache-drive configuration sector, and formatting and mounting `Z:`, all in the original order. It then stops where **D3D8 initialization reads NV2A register `0xFD001804`**. That is the hardware boundary outside the kernel and the starting point of the next task (D3D8 HLE). HLE modules use only the runtime's new contracts (`GuestCpu`, `GuestExecutor`, `Environment`, `HleCall`, `GuestHeap`) and know nothing of the lifter ABI. Twenty-seven kernel unit checks pass without game data and now run in CI.

## Process

1. Disassembled the entry point to confirm the start sequence (design §2), and derived "StackBase = TlsData + TlsDataSize" from how `fs:[0x28]`, `fs:[0x20]`, `fs:[4]`, `KTHREAD+0x28` and `ETHREAD+0x12C` are used and from the negative TLS index. xboxrecomp imitates these with fake blocks at fixed addresses; we build the real layout per thread.
2. Built the runtime contracts, adding `GuestExecutor::CallGuest` because the kernel must run guest callbacks (`KeSynchronizeExecution`).
3. Thread exit unwinds native frames with SEH, and MSVC's default `/EHsc` skips C++ destructors during that unwind, so the build moved to `/EHa`.
4. The first frontier was `NtOpenFile`. With the file layer (VFS + services) in place, XAPI created `T:` and `U:`, then failed to open `\Device\Harddisk0\Partition0` and went to `HalReturnToFirmware`.
5. Opening Partition0 as a raw device and tracing IOCTLs showed the real sequence: read and write of the cache-configuration sector (offset 0x800), geometry and partition info of Partition5, raw format writes, `FSCTL_DISMOUNT_VOLUME`, then the `Z:` link. Opening a partition root as a volume object (raw writes accepted and dropped) got through it.
6. Found 10 indirect calls skipped for lack of a target (`0x0018AFB0`–`0x0018C3C0`) and added a disasm seed path (`src/game/jsrf/recomp/*.json`) to `regenerate.py` (8,716 → 8,721 functions).
7. Reported faults as guest addresses (host − base modulo 2³²), which showed the access wrapped on Win32 is `0xFD001804` (NV2A MMIO).
8. Mistakes made: batch replacements in Python turned `\n`, `\D`, `\r`, `\b` and `\t` in C strings into control characters several times. All were found and fixed; later edits involving backslashes used the Edit tool only.

## Verification

The table in the Korean section applies: regeneration with one seed file (8,721 functions, one `_gen` wrap, clean submodule); Debug and Release builds with zero warnings (Release 1.6 min); `rexbox_kernel_probe` 27 checks and 0 failures in both configurations; `rejsrf_decomp_check` 6 cases and 0 differences; the boot (Debug and Release) ends thread 1 normally and stops thread 2, after XAPI initialization, with `fault C0000005, read at guest FD001804` in about 1.7 s; no skipped indirect calls after the seeds. Waiting on thread termination needs a real guest thread and is not in the probe; the boot's normal entry-thread exit covers that path.

## Remaining

* Next task: D3D8 HLE, starting with XDK 4134 D3D8 function identification and title bindings, then device creation (the `Direct3D_CreateDevice` family) at the API level (design i001 §4, `docs/analysis/boot-frontier.md`).
* Timers (`KeSetTimer`) and DPCs (`KeInsertQueueDpc`) never run; whether they are needed is revisited after the D3D and DSOUND HLE.
* `NtSuspendThread` cannot stop a thread that is already running (it only records the count).
* `XboxHardwareInfo` and the AV values are provisional until D3D's use of them is analysed.
