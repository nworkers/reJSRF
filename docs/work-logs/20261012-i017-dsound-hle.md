# Issue #17 작업 로그 — DSOUND HLE

작업 지시: [20261012-i017](../work-orders/20261012-i017-dsound-hle.md) · 설계: [20261012-i017](../design/20261012-i017-dsound-hle.md)

## 요약

게임이 부르는 DSOUND 함수 50개를 HLE로 바꾸고, SDL3 위에 플랫폼 오디오 계약을 만들었다. 부팅은 더 이상 APU 레지스터를 읽지 않고, `DirectSoundCreate`(호스트 장치 48 kHz 스테레오)를 지나 게임 스레드 4개가 돈다. 이어서 **주 스레드가 `D:\Media\Sounds\dsstdfx.bin`을 비동기로 읽고 완료 루틴(사용자 APC)을 기다리는 곳**에서 멈춘다. 커널 HLE가 사용자 APC를 전달하지 않기 때문이고, 다음 task로 남긴다.

1. **원본 의미.** `Lock`의 나눔, `Unlock`이 아무것도 하지 않음, `Stop`의 위치 저장과 `Play`의 재개, 끝난 비반복 버퍼의 위치 0, 쓰기 커서, 상태 비트를 lift 본문(`CDirectSoundBuffer_*`, `CMcpxBuffer_*`)에서 확인해 그대로 구현했다.
2. **효과 이미지.** `dsstdfx.bin`의 효과 표가 평문이고 코드 구간만 암호화되어 있음을 원본 다운로드 코드(`0x001A19D6`, `0x001A1769`)에서 확인했다. HLE는 이미지를 복사해 표로 서술자를 만들고, `GetEffectData`/`SetEffectData`는 원본처럼 상태 구간을 복사한다.
3. **믹서.** 원본 `Unlock`이 비어 있으므로 믹서는 매 렌더마다 게스트 메모리를 직접 읽는다(PCM 8/16, Xbox ADPCM, 선형 보간 재표본화, 볼륨, 루프 구간, 믹스 빈 → 스테레오). 장치가 없거나 `REXBOX_AUDIO=none`이면 pacing 스레드가 같은 렌더를 실시간으로 돌려 커서가 움직인다.
4. **포인터로만 참조되는 함수.** `DirectSoundCreate` 뒤 게임이 시작하는 스레드 4개와 파일 읽기 메서드가 lift되지 않아 건너뛰어졌다. `scripts/recomp/find_pointer_targets.py`로 같은 부류 162개를 찾아 seed로 넣었다(lift 함수 8,852 → 9,015, 미해결 스텁 109 → 105).

## 과정

1. 게임 코드에서 DSOUND 섹션으로 가는 `call`/`jmp rel32`를 바이트 스캔해 50개 함수와 `ret n`을 얻었다(capstone 선형 디스어셈블은 `.text`의 데이터에서 멈춰 쓸 수 없었다). 꼬리 호출 `jmp` 2종을 포함한다. 이름 없는 대상 3개는 원본이 하드웨어에 닿지 않아(`SetCooperativeLevel`/`Compact` 꼴 스텁, `DirectSoundUseFullHRTF`) lift된 채로 두었다.
2. 원본 `Lock`, `GetCurrentPosition`, `GetStatus`, `Stop`, `Play`, `SetCurrentPosition`, `SetBufferData`, `GetSpeakerConfig`, `DownloadEffectsImage`, `GetEffectData`를 읽어 의미를 정했다([analysis: DSOUND §2–3](../analysis/dsound.md)).
3. re2DJ(BSD-3)의 SDL3 오디오(`host_audio.cpp`, `sdl3_mixer_audio_backend.cpp`, `legacy_audio_buffer.h`)를 정책대로 먼저 읽었다. `Play` 때 복사본을 SDL_mixer 트랙에 넣는 모델이라 Xbox의 빈 `Unlock`과 맞지 않아 코드는 가져오지 않았다. SDL 타입을 플랫폼 계층에 숨기고 장치 없이도 계속 도는 구조만 참고했다(SDL_mixer 의존도 더하지 않음).
4. 플랫폼 계약 `audio.h`와 SDL3 구현 `audio_sdl.cpp`(`SDL_OpenAudioDeviceStream` + get 콜백, 장치 주기 512프레임, null pacing 스레드), `rexbox_hle_dsound`를 6개 파일로 나눠 구현했다. 렌더하지 않는 설정 26개는 `AcceptSetting<n>` 템플릿 하나로 받고, `check_hle_pops.py`가 템플릿 인자를 pop 수로 읽게 했다.
5. `rexbox_dsound_probe`(48개)를 kernel probe와 같은 가짜 실행기로 만들고, 수동 출력으로 믹서를 직접 돌려 시간에 의존하지 않게 했다. ADPCM 기대값은 IMA 단계표로 손으로 계산했다(0 니블도 단계 색인이 0이 될 때까지 `step >> 3`씩 더해 1018…1021이 된다).
6. 첫 부팅: `DirectSoundCreate`를 지났지만 `0x0013B180` 등 스레드 루틴 4개와 vtable 메서드 `0x00178F40`이 "no target"으로 건너뛰어졌고, 효과 이미지가 비어(효과 0개) 그 뒤 파일 객체의 null vtable 호출과 `0x909090C0` 읽기 fault가 났다. 놓친 함수 탐색 스크립트를 만들어 162개 seed를 넣고 재생성했다. 남은 후보 3개는 다른 함수 범위 안에 있어 lift되지 않는다(미확정).
7. 두 번째 부팅: 건너뛴 간접 호출 0건. 주 스레드가 `NtReadFile(dsstdfx.bin, ApcRoutine)` 뒤 `NtWaitForSingleObjectEx`에서 멈춘다(watchdog). `REXBOX_TRACE_FILES`와 `REXBOX_HLE_TRACE`로 파일과 대기 대상을 확인했다.

# Issue #17 work log — DSOUND HLE

Work order: [20261012-i017](../work-orders/20261012-i017-dsound-hle.md) · Design: [20261012-i017](../design/20261012-i017-dsound-hle.md)

## Summary

The 50 DSOUND functions the game calls now run on HLE, over a new platform audio contract on SDL3. Boot no longer reads APU registers. It passes `DirectSoundCreate` (host device, 48 kHz stereo), four game threads run, and then **the main thread reads `D:\Media\Sounds\dsstdfx.bin` asynchronously and waits for its completion routine (a user APC)**. The kernel HLE delivers no user APCs, which is left for the next task.

1. **Original semantics.** The lifted bodies (`CDirectSoundBuffer_*`, `CMcpxBuffer_*`) confirmed how `Lock` splits, that `Unlock` does nothing, that `Stop` saves the position and `Play` resumes from it, that a finished one-shot reads position 0, the write cursor and the status bits; the HLE implements them as they are.
2. **The effects image.** The original download code (`0x001A19D6`, `0x001A1769`) showed that `dsstdfx.bin`'s effect table is plaintext and only the code region is encrypted. The HLE copies the image and builds the descriptor from the table; `GetEffectData`/`SetEffectData` copy state segments as the original does.
3. **The mixer.** Because the original `Unlock` is empty, the mixer reads guest memory directly on every render (8/16-bit PCM, Xbox ADPCM, linear-interpolation resampling, volume, loop region, mix bins folded to stereo). Without a device, or with `REXBOX_AUDIO=none`, a pacing thread runs the same render in real time, so cursors move.
4. **Functions reached only through pointers.** After `DirectSoundCreate`, the four threads the game starts and a file-read method had not been lifted and were skipped. `scripts/recomp/find_pointer_targets.py` found 162 such functions, now seeded (lifted functions 8,852 → 9,015, unresolved stubs 109 → 105).

## Process

1. A byte scan of `call`/`jmp rel32` from game code into the DSOUND section gave the 50 functions and their `ret n` (capstone's linear disassembly stops at data inside `.text` and could not be used), including two tail-call `jmp`s. The three unnamed targets stay lifted because their originals touch no hardware (`SetCooperativeLevel`/`Compact`-shaped stubs and `DirectSoundUseFullHRTF`).
2. The originals of `Lock`, `GetCurrentPosition`, `GetStatus`, `Stop`, `Play`, `SetCurrentPosition`, `SetBufferData`, `GetSpeakerConfig`, `DownloadEffectsImage` and `GetEffectData` fixed the semantics ([analysis: DSOUND §2–3](../analysis/dsound.md)).
3. Per the policy, re2DJ's (BSD-3) SDL3 audio (`host_audio.cpp`, `sdl3_mixer_audio_backend.cpp`, `legacy_audio_buffer.h`) was read first. It puts a copy taken at `Play` into an SDL_mixer track, which does not fit the Xbox's empty `Unlock`, so no code was taken; only its structure (SDL types hidden in the platform layer, running on without a device) was a reference, and no SDL_mixer dependency was added.
4. The platform contract `audio.h` with the SDL3 implementation `audio_sdl.cpp` (`SDL_OpenAudioDeviceStream` with a get callback, a 512-frame device period, a null pacing thread), and `rexbox_hle_dsound` in six files. The 26 settings that are not rendered share one `AcceptSetting<n>` template, and `check_hle_pops.py` reads the template argument as the pop count.
5. `rexbox_dsound_probe` (48 checks) uses the kernel probe's fake executor and drives the mixer by hand through the manual output, so nothing depends on time. The ADPCM expectations were worked out by hand from the IMA step table (zero nibbles still add `step >> 3` until the step index reaches 0, giving 1018…1021).
6. First boot: past `DirectSoundCreate`, but four thread routines (`0x0013B180` and others) and the vtable method `0x00178F40` were skipped as "no target"; the effects image came back empty (0 effects), followed by a null vtable call on the file object and a read fault at `0x909090C0`. The missed-function scan was written, 162 seeds added and the code regenerated. Three remaining candidates lie inside other functions' ranges and are not lifted (unresolved).
7. Second boot: no skipped indirect calls. The main thread stops in `NtWaitForSingleObjectEx` after `NtReadFile(dsstdfx.bin, ApcRoutine)` (watchdog); `REXBOX_TRACE_FILES` and `REXBOX_HLE_TRACE` identified the file and the wait.

## Verification

The table in the Korean section applies: Debug and Release builds with zero warnings on our targets; `rexbox_dsound_probe` 48/48 (Debug and Release); kernel probe 28/28; decomp check 6/6; d3d8 check 13,557/0; `check_hle_pops.py` 0 mismatches (the 50 DSOUND exports included); boot with `REXBOX_AUDIO=none` and `REXBOX_DISPLAY=none` past `DirectSoundCreate` with no skipped indirect calls, stopping at the APC wait of the `dsstdfx.bin` read; boot with host audio printing `[dsound] audio output: host device, 48000 Hz stereo`. Hearing sound could not be checked: the game stops before it creates buffers.
