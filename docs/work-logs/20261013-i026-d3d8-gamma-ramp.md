# Issue #26 작업 로그 — D3D8 감마 램프를 화면에 적용

작업 지시: [20261013-i026](../work-orders/20261013-i026-d3d8-gamma-ramp.md) · 설계: [20261013-i026](../design/20261013-i026-d3d8-gamma-ramp.md)

## 요약

`D3DDevice_SetGammaRamp`가 이제 램프를 저장하고, `GetGammaRamp`는 그 값을 돌려준다. 램프는 `Swap`의 표시와 frame dump에 적용된다. 단위 램프이면 지금처럼 blit하고, 아니면 GLSL 셰이더가 256×1 램프 텍스처를 찾는다. lift된 원본에서 Xbox `D3DGAMMARAMP`가 768바이트 BYTE 표(R, G, B 각 256)임을 확인했다. 로고 동안 게임은 매 프레임 단위 램프를 설정하므로 지금 화면은 바뀌지 않는다. 페이드가 일어나는 지점(로고 진입·종료)에서 효과가 보일 것이다.

## 과정

1. 원본 `SetGammaRamp`(`0x0018CB60`)와 도우미 `0x0018E584`를 읽었다. 768바이트를 디바이스 램프 칸으로 복사하고, IMMEDIATE이면 RAMDAC 팔레트(`0x6813C8/9`)에 R, G, B 순으로 256번 쓴다.
2. 순수 모듈 `d3d8_gamma`(단위 판정, CPU 적용, 램프 텍셀, present 셰이더)를 만들고 `rexbox_d3d8_probe`에 8건을 더했다.
3. `d3d8_gl_targets`에 감마 present 경로(빈 VAO의 전체 화면 삼각형, `texelFetch`)를 넣고, 덤프에 CPU 적용을 넣었다.
4. `REXBOX_D3D8_TRACE`에 단위가 아닌 램프 기록을 넣었다. 20초 동안 기록이 없어, 로고 단계의 램프가 단위임을 확인했다.
5. GL 경로를 검증하려고 임시로 절반 램프를 강제했다(검증 뒤 제거). 창 프레임버퍼를 다시 읽은 로고 중앙과 덤프가 모두 (8, 28, 123)에서 (4, 14, 61)이 되었다(숨김 창·보이는 창 모두).

## 남은 일

* 실제 페이드는 로고에서 넘어가야 볼 수 있다(i025의 다음 task).
* watchdog의 `_Exit`로 끝난 실행 중 일부가 종료 처리 중에 걸린 프로세스(스레드 0개)로 남아 실행 파일을 잠근다. GL 드라이버가 올라온 뒤 생긴다. 링크가 막히면 실행 파일 이름을 바꿔 피한다. 원인 조사는 따로 한다.

# Issue #26 work log — apply the D3D8 gamma ramp to the screen

Work order: [20261013-i026](../work-orders/20261013-i026-d3d8-gamma-ramp.md) · Design: [20261013-i026](../design/20261013-i026-d3d8-gamma-ramp.md)

## Summary

`D3DDevice_SetGammaRamp` now stores the ramp, and `GetGammaRamp` returns it. The ramp is applied to the `Swap` present and to frame dumps: a blit when it is identity, otherwise a GLSL shader that looks each channel up in a 256×1 ramp texture. The lifted original confirmed that the Xbox `D3DGAMMARAMP` is a 768-byte BYTE table (256 each of R, G, B). During the logo the game sets an identity ramp every frame, so the screen does not change yet. The effect will show where fades happen (entering and leaving a logo).

## Process

1. Read the original `SetGammaRamp` (`0x0018CB60`) and its helper `0x0018E584`. It copies 768 bytes into the device's ramp slot and, with IMMEDIATE, writes the RAMDAC palette (`0x6813C8/9`) 256 times, R, G, B.
2. Added the pure module `d3d8_gamma` (identity test, CPU application, ramp texels, present shaders) and 8 checks in `rexbox_d3d8_probe`.
3. Added the gamma present path to `d3d8_gl_targets` (a fullscreen triangle from an empty VAO, `texelFetch`) and the CPU application to dumps.
4. `REXBOX_D3D8_TRACE` now reports non-identity ramps. None appeared over 20 s, which confirms the logo stage's ramp is identity.
5. To check the GL path, a half ramp was forced temporarily (removed afterwards). The logo center read back from the window framebuffer and the dump both went from (8, 28, 123) to (4, 14, 61), in hidden and visible windows.

## Verification

The table in the Korean section applies: Debug/Release builds with zero warnings on our targets; `rexbox_d3d8_probe` 81 checks with 0 failures; kernel and DSOUND probes 42/0 and 48/0; `rejsrf_d3d8_check` 14,018 cases with 0 differences; `check_hle_pops.py` 0 mismatches (`SetGammaRamp` pops 2 arguments, original `ret 8`); the forced half-ramp test darkened both the window and the dump by half.

## Remaining

* Real fades are visible only once the boot moves past the logo (the next task from i025).
* Some runs that end through the watchdog's `_Exit` remain as processes stuck in teardown (zero threads) that keep the executable locked. This happens after the GL driver has loaded. When it blocks the link, rename the executable. The cause is to be investigated separately.
