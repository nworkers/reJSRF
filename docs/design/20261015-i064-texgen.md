# 설계: 텍스처 좌표 생성과 텍스처 변환 (issue #64)

## 1. 문제

* 고정 기능 그리기에서 두 기능이 적용되지 않았다. 기본 데모 구간에서 프레임당 10~39개 그리기가 해당한다(i062의 `unimplemented per frame:`).
  * 텍스처 좌표 생성: `D3DTSS_TEXCOORDINDEX`의 상위 16비트
  * 텍스처 변환: `D3DTSS_TEXTURETRANSFORMFLAGS`와 `D3DTS_TEXTURE0..3`
* 임시 추적(프레임 2,800·3,100)에서 본 것은 다음과 같다(**확인됨**).

| 스테이지 | 좌표 | 플래그 | 행렬 | 해석 |
|---|---|---|---|---|
| 0 | `CAMERASPACENORMAL` | `COUNT2` | 배율 `(0.5, -0.5)`, 넷째 행 `(0.5, 0.5)` | 법선 기반 환경 맵 |
| 1 | `CAMERASPACENORMAL` | `COUNT2` | u = N·(벡터) + 0.25, v = 0 | 1차원 램프. 캐릭터 셀 셰이딩으로 **추정** |
| 0 | 세트 0(2D) 그대로 | `COUNT2` | 단위 행렬, **셋째** 행에 이동량(프레임마다 바뀜) | 스크롤 텍스처 |

* 법선 생성은 모두 FVF `0x112`(XYZ | NORMAL | TEX1), 256×256 텍스처다.
* 스크롤 행렬의 이동량이 셋째 행에 있다. 이는 D3D가 2D 세트를 `(u, v, 1, 0)`으로 채운다는 뜻이다. GL은 `(u, v, 0, 1)`로 채운다.

## 2. 설계

* **좌표를 스테이지별로**: 고정 기능 정점 처리에서는 정점 셰이더가 활성 스테이지마다 좌표 하나(`v_tex<s>`)를 쓰고, 프래그먼트 스테이지 s는 그것을 읽는다(키의 `stage_coords`).
  * 정점 프로그램 경로는 그대로 둔다. 프로그램이 `v_tex0..3`을 쓰고, 스테이지는 `v_tex<TEXCOORDINDEX>`를 읽는다. D3D에서도 생성과 변환은 고정 기능 정점 처리에만 속한다.
* **키**:
  * 스테이지마다 `tex_gen`과 `tex_transform`을 둔다. `tex_gen`은 0 없음, 1 카메라 공간 법선, 2 위치, 3 반사 벡터다. `tex_transform`은 `COUNTn | PROJECTED`이고, 꺼져 있으면 0이다.
  * 키 전체에는 `has_normal`과 `normalize_normals`(`D3DRS_NORMALIZENORMALS`)를 둔다.
* **정점 셰이더**(스테이지마다):
  1. 입력:
     * 법선 생성: `(n_eye, 1)`, n_eye = 법선 × (World·View)의 3×3 역전치. `NORMALIZENORMALS`이면 정규화한다.
     * 위치 생성: `(p_eye, 1)`, p_eye = 위치 × World·View
     * 반사 벡터 생성: `(reflect(normalize(p_eye), n_eye), 1)`
     * 생성이 없을 때: 변환이 있으면 D3D 방식으로 채운다. 1개면 `(x, 1, 0, 0)`, 2개면 `(u, v, 1, 0)`, 3개면 `(x, y, z, 1)`. 변환이 없으면 지금처럼 그대로 쓴다.
  2. 변환(`COUNTn`): `D3DTS_TEXTURE<s>` × 입력. 행 벡터 규약이다.
  3. `PROJECTED`: 마지막 출력 성분(n번째)을 `.w`에 두고, 프래그먼트에서 나눈다. 원근 보간이 맞게 하려는 것이다.
* **유니폼**:
  * `u_world_view`(위치·반사 생성일 때)
  * `u_normal_matrix`(법선·반사 생성일 때, CPU에서 계산한 역전치)
  * `u_tex_matrix<s>`(변환이 켜진 스테이지)
* **법선 속성**: FVF에 법선이 있으면 속성 7로 묶는다. 생성이 법선을 읽는데 FVF에 없으면 0을 쓰고 한 번 보고한다.
* **보고하는 것**:
  * XYZRHW 정점에서의 생성·변환은 적용하지 않고 보고한다. D3D의 동작을 확인하지 못했고, 게임에서도 나오지 않았다.
  * 4 이상의 생성 방식과, 알 수 없는 플래그도 보고한다.

## 3. 검증

| 데모 | `unimplemented per frame:`에 `texgen`·`texture transform` 없음. 셰이더 컴파일 오류 없음. 캐릭터에 명암 띠 |

# Design: texture coordinate generation and texture transforms (issue #64)

## 1. Problem

* Fixed-function draws ignored two features. The default demo has 10–39 such draws per frame (i062's `unimplemented per frame:`).
  * Texture coordinate generation: the high 16 bits of `D3DTSS_TEXCOORDINDEX`
  * Texture transforms: `D3DTSS_TEXTURETRANSFORMFLAGS` with `D3DTS_TEXTURE0..3`
* A temporary trace (frames 2,800 and 3,100) showed (**confirmed**):

| Stage | Coordinates | Flags | Matrix | Reading |
|---|---|---|---|---|
| 0 | `CAMERASPACENORMAL` | `COUNT2` | scale `(0.5, -0.5)`, fourth row `(0.5, 0.5)` | normal-based environment map |
| 1 | `CAMERASPACENORMAL` | `COUNT2` | u = N·(a vector) + 0.25, v = 0 | a 1D ramp, **inferred** to be the characters' cel shading |
| 0 | set 0 (2D) passed through | `COUNT2` | identity with a translation in the **third** row, changing per frame | scrolling texture |

* All normal generation is on FVF `0x112` (XYZ | NORMAL | TEX1) with 256×256 textures.
* The scrolling translation sits in the third row, so D3D pads a 2D set as `(u, v, 1, 0)`. GL pads it as `(u, v, 0, 1)`.

## 2. Design

* **Per-stage coordinates**: with fixed-function vertex processing the vertex shader writes one coordinate per active stage (`v_tex<s>`), and fragment stage s reads it (the key's `stage_coords`).
  * The vertex-program path is unchanged: the program writes `v_tex0..3`, and a stage reads `v_tex<TEXCOORDINDEX>`. In D3D, too, generation and transforms belong to fixed-function vertex processing only.
* **Key**:
  * Per stage, `tex_gen` and `tex_transform`. `tex_gen` is 0 none, 1 camera-space normal, 2 position, 3 reflection vector. `tex_transform` is `COUNTn | PROJECTED`, or 0 when off.
  * For the whole key, `has_normal` and `normalize_normals` (`D3DRS_NORMALIZENORMALS`).
* **Vertex shader**, per stage:
  1. Input:
     * Normal generation: `(n_eye, 1)`, where n_eye is the normal times the inverse transpose of World·View's 3×3, normalized under `NORMALIZENORMALS`.
     * Position generation: `(p_eye, 1)`, where p_eye is the position times World·View.
     * Reflection generation: `(reflect(normalize(p_eye), n_eye), 1)`.
     * No generation: with a transform, the set is padded the D3D way: `(x, 1, 0, 0)` for 1 component, `(u, v, 1, 0)` for 2, `(x, y, z, 1)` for 3. Without a transform it passes through as before.
  2. Transform (`COUNTn`): `D3DTS_TEXTURE<s>` applied to the input, in the row-vector convention.
  3. `PROJECTED`: the last output component (the n-th) goes to `.w`, and the fragment stage divides by it, which keeps perspective-correct interpolation.
* **Uniforms**:
  * `u_world_view` (position and reflection generation)
  * `u_normal_matrix` (normal and reflection generation; the inverse transpose, computed on the CPU)
  * `u_tex_matrix<s>` (stages with a transform)
* **Normal attribute**: an FVF normal is bound at attribute 7. When generation reads a normal the FVF lacks, zero is used and reported once.
* **Reported, not applied**:
  * Generation and transforms on XYZRHW vertices. D3D's behavior there is not confirmed, and the game does not do it.
  * Generation modes 4 and up, and flags that are not understood.
