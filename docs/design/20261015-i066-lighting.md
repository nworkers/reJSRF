# 설계: 고정 기능 조명 (issue #66)

## 1. 문제

* `D3DRS_LIGHTING`이 켜진 고정 기능 그리기가 조명 없이 정점 색으로 그려졌다(데모 구간 프레임당 0~14개).
* `SetLight`·`LightEnable`·`SetMaterial`은 받기만 하고 값을 저장하지 않았다.
* 임시 추적에서 게임이 쓰는 값은 다음과 같았다(**확인됨**).

| 항목 | 값 |
|---|---|
| 광원 | 방향광 하나: 확산·정반사 `(1, 1, 1)`, 주변광 0, 감쇠 `(1, 0, 0)`. 방향은 장면마다 바뀜 |
| 렌더 상태 | `COLORVERTEX` 1, 재질 원천 diffuse COLOR1·specular COLOR2·ambient·emissive MATERIAL, `AMBIENT` `0xFFFFFF`, `SPECULARENABLE` 0, `LOCALVIEWER` 0, `NORMALIZENORMALS` 0 |
| 재질 | 확산·주변광 1, 정반사 0, 방출 0, power 50 |
| 정점 형식 | FVF `0x112`(XYZ·법선·TEX1)와 `0x1118`(XYZB2·법선·TEX1, `VERTEXBLEND` 0) |

* 정점 형식에 색이 없으므로 확산 색은 재질의 1이다.
* 조명 결과는 방출 0 + 주변광 1×1 + 확산 1×N·L ≥ 1이고, 잘려서 **흰색**이다. 조명 없이 그리던 지금도 정점 색이 흰색이므로, 이 데모의 화면은 바뀌지 않을 것으로 예상한다. 명암은 i064의 법선 생성 램프가 맡는다.
* 그래도 다른 장면이나 다른 상태에서 맞게 그리려면 D3D 조명식이 필요하다.

## 2. 설계

* **상태(`d3d8_state`)**:
  * `PipelineState`에 `lights`(인덱스별 `Light`, `SetLight`·`LightEnable`이 늘림, 최대 256)와 `material`을 둔다.
  * `D3DLIGHT8`(104바이트)과 `D3DMATERIAL8`(68바이트)은 PC 배치로 읽는다(**추정**, 게임 값과 맞음).
* **키(`FixedFunctionKey`)**: 고정 기능 정점 처리이고 XYZRHW가 아닐 때만 조명을 켠다.
  * `lighting`, `local_viewer`
  * 켜진 광원의 종류: 인덱스 순서, 최대 8개
  * 색 원천 4개(확산, 주변광, 정반사, 방출)
    * `COLORVERTEX`가 꺼져 있으면 모두 재질이다.
    * COLOR1·COLOR2인데 정점에 그 색이 없으면 재질로 바꾼다.
  * 정반사 항은 기존 `specular_enable`로 켠다.
* **정점 셰이더**(카메라 공간, 광원별로 펼침):
  * 확산 = 방출 + `AMBIENT`·Ca + Σ atten·spot·(La·Ca + Ld·Cd·max(N·L, 0))
  * 정반사 = Σ atten·spot·Ls·Cs·max(N·H, 0)^power. N·L > 0일 때만 더한다(**추정**).
  * 방향광: L = −방향
  * 점·스폿: L = normalize(광원 위치 − 정점). 감쇠는 거리 ≤ range이면 1/(a0 + a1·d + a2·d²), 아니면 0이다.
  * 스폿: ρ = dot(−L, 방향)
    * ρ > cos(θ/2)이면 1
    * ρ ≤ cos(φ/2)이면 0
    * 사이는 ((ρ − cos(φ/2)) / (cos(θ/2) − cos(φ/2)))^falloff
  * H = normalize(L + V)
    * V는 `LOCALVIEWER`이면 normalize(−정점 위치)다.
    * 아니면 (0, 0, −1)이다. D3D 카메라 공간은 +z를 바라본다(**추정**).
  * 결과는 0..1로 자른다. 알파는 확산 원천의 알파, 정반사 출력의 알파는 정반사 원천의 알파다.
* **유니폼**:
  * 재질 4색과 power, `AMBIENT`
  * 광원별 색 3개, 위치(카메라 공간)와 range, 방향(카메라 공간, 단위), 감쇠와 falloff, cos(θ/2)·cos(φ/2)
  * 광원의 위치·방향은 CPU에서 View로 옮긴다.
* **보고**: 알 수 없는 광원 종류, 9개 이상 켜진 광원, 법선이 없는 형식의 조명. "조명 미구현" 보고는 없앤다.

## 3. 검증

| 검증 | 기대 |
|---|---|
| `rexbox_d3d8_probe` | 방향광(재질 원천), 점·스폿·정반사·로컬 뷰어·정점 색 원천의 GLSL, 키 구분 |
| 데모 | 미구현 보고 없음. 셰이더 오류 없음. 조명 그리기의 모습이 이전과 같음(조명 결과 흰색) |
| 회귀 | Debug·Release, probe 3종, `rejsrf_d3d8_check`, `rejsrf_decomp_check`, `check_hle_pops.py` |
| 성능 | 이전 빌드와 번갈아 CPU 열 비교 |

# Design: fixed-function lighting (issue #66)

## 1. Problem

* Fixed-function draws with `D3DRS_LIGHTING` on were drawn with vertex colors, unlit (0–14 per frame in the demo window).
* `SetLight`, `LightEnable` and `SetMaterial` were accepted without keeping their values.
* A temporary trace showed the game's values (**confirmed**):

| Item | Value |
|---|---|
| Light | one directional light: diffuse and specular `(1, 1, 1)`, no ambient, attenuation `(1, 0, 0)`; the direction changes by scene |
| Render states | `COLORVERTEX` 1; material sources diffuse COLOR1, specular COLOR2, ambient and emissive MATERIAL; `AMBIENT` `0xFFFFFF`; `SPECULARENABLE` 0; `LOCALVIEWER` 0; `NORMALIZENORMALS` 0 |
| Material | diffuse and ambient 1, specular 0, emissive 0, power 50 |
| Vertex formats | FVF `0x112` (XYZ, normal, TEX1) and `0x1118` (XYZB2, normal, TEX1, with `VERTEXBLEND` 0) |

* The formats have no vertex color, so the diffuse color is the material's 1.
* The lit result is emissive 0 + ambient 1×1 + diffuse 1×N·L, at least 1, which clamps to **white**. The unlit draws already used white vertex color, so the demo's picture is expected not to change. Shading comes from i064's normal-generated ramp.
* D3D's lighting equation is still needed for other scenes and states.

## 2. Design

* **State (`d3d8_state`)**:
  * `PipelineState` gains `lights` (a `Light` per index, grown by `SetLight` and `LightEnable`, up to 256) and `material`.
  * `D3DLIGHT8` (104 bytes) and `D3DMATERIAL8` (68 bytes) are read in the PC layout (**inferred**; the game's values fit).
* **Key (`FixedFunctionKey`)**: lighting is on only with fixed-function vertex processing and non-XYZRHW vertices.
  * `lighting`, `local_viewer`
  * The enabled lights' types, in index order, up to 8
  * The four color sources (diffuse, ambient, specular, emissive)
    * Without `COLORVERTEX` they are all the material.
    * COLOR1 or COLOR2 falls back to the material when the vertex lacks that color.
  * The existing `specular_enable` turns the specular term on.
* **Vertex shader** (camera space, unrolled per light):
  * diffuse = emissive + `AMBIENT`·Ca + Σ atten·spot·(La·Ca + Ld·Cd·max(N·L, 0))
  * specular = Σ atten·spot·Ls·Cs·max(N·H, 0)^power, added only where N·L > 0 (**inferred**).
  * Directional: L = −direction.
  * Point and spot: L = normalize(light position − vertex). The attenuation is 1/(a0 + a1·d + a2·d²) within the range, 0 beyond it.
  * Spot: ρ = dot(−L, direction).
    * 1 above cos(θ/2)
    * 0 at or below cos(φ/2)
    * between them, ((ρ − cos(φ/2)) / (cos(θ/2) − cos(φ/2)))^falloff
  * H = normalize(L + V).
    * With `LOCALVIEWER`, V = normalize(−vertex position).
    * Otherwise V = (0, 0, −1), since D3D camera space looks down +z (**inferred**).
  * Results are clamped to 0..1. The alpha comes from the diffuse source, and the specular output's alpha from the specular source.
* **Uniforms**:
  * The material's four colors and power, and `AMBIENT`
  * Per light: three colors, the position (camera space) with the range, the direction (camera space, unit), the attenuation with the falloff, and cos(θ/2) and cos(φ/2)
  * Light positions and directions are moved to camera space by View on the CPU.
* **Reports**: unknown light types, more than 8 enabled lights, and lighting with a format that has no normal. The "lighting not implemented" report is gone.
