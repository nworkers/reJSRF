# 설계: MXCSR 모델링과 SSE 정수 변환의 반올림 (issue #48)

## 1. 요구사항

* 데모 실행 중 `[recomp] untranslated instruction at 0015F0F1: stmxcsr dword ptr [0x265150]`가 나온다. 그 위치는 실제로 실행되는 게임 코드다.
* lift되지 않은 명령 목록(`gen/jsrf_us/recomp-summary/summary.json`, 35종)은 대부분 데이터를 코드로 읽은 것으로 보인다(**추정**). 이번 작업은 실제로 실행되는 `stmxcsr` 하나를 다룬다. 나머지 분류는 별도 작업으로 둔다.

## 2. 확인한 것

* **확인됨**(lift 코드): `sub_0015F0F0`(cdecl, 인자 4개)은 다음을 한다.
  1. `stmxcsr [0x265150]`로 MXCSR을 저장한다.
  2. 저장한 값의 비트 13~14(반올림 제어 RC)를 검사한다(`test ah, 0x60`).
  3. RC가 0(nearest)이 아니면 `0x8000FFFF`(E_UNEXPECTED)를 돌려준다. RC가 0이면 인자를 검사하고 본 작업으로 간다.
* 이 함수는 XDK 심볼 DB에 없다(게임 코드 또는 식별되지 않은 라이브러리, **미확정**). `0x0015F3A7`과 `0x0015F878` 두 곳에서 부른다.
* 지금은 `stmxcsr`가 아무것도 저장하지 않는다. 그래서 검사는 0x265150에 원래 있던 값(0으로 보임)을 읽고, 결과적으로 올바른 쪽으로 간다(**추정**). 하지만 그것은 우연이다.
* 게임에는 `ldmxcsr`가 없다. 그래서 게스트 MXCSR은 리셋 값 0x1F80(모든 예외 마스크, RC=nearest)에서 바뀌지 않는다.
* **같은 계열의 버그**: lifter는 `cvtss2si`/`cvtsd2si`를 C의 `(int32_t)` 캐스트로 번역한다. 캐스트는 버림이지만, 하드웨어는 MXCSR RC(기본 nearest-even)로 반올림한다. 게임에 `cvtss2si` 6곳, `cvttss2si` 4곳이 있다.
  * 범위를 벗어난 값을 캐스트하는 것은 C에서 정의되지 않은 동작이다. 하드웨어는 integer indefinite(0x80000000)를 돌려준다.

## 3. 설계 (xboxrecomp fork, `fix/mxcsr` → `rejsrf`; upstream PR #198에 합침)

* **게스트 MXCSR**: x87 제어 워드(`g_fp_control_word`)와 같은 방식으로 다룬다.
  * `RECOMP_TLS uint32_t g_mxcsr`를 둔다. 리셋 값은 0x1F80이다. 스레드 상태이므로 TLS다.
  * 호스트 MXCSR은 바꾸지 않는다. x87 `fldcw`가 호스트에 닿지 않는 것과 같다.
* **lifter**:
  * `stmxcsr m32`는 `MEM32(m) = g_mxcsr`로 번역한다.
  * `ldmxcsr m32`는 `g_mxcsr = MEM32(m)`로 번역한다.
  * 둘 다 EFLAGS를 바꾸지 않는다(`_EFLAGS_PRESERVE`).
* **정수 변환**: `recomp_cvt_si32(value, mxcsr, truncate)`를 둔다.
  * `cvtss2si`/`cvtsd2si`는 `g_mxcsr`의 RC로 반올림한다. x87과 인코딩이 같으므로 `recomp_frndint`를 재사용한다.
  * `cvttss2si`/`cvttsd2si`는 버린다.
  * NaN, 무한대, 범위 밖의 값은 0x80000000이다.
* **예외 플래그**(MXCSR 비트 0~5)는 모델링하지 않는다. 저장되는 값의 플래그는 0이다. x87 상태 워드의 예외 바이트를 모델링하지 않는 것과 같다.
* **reJSRF**:
  * `rexbox_recomp`(`recomp_abi.c`)가 `g_mxcsr`를 정의하고, 스레드를 초기화할 때 0x1F80으로 둔다.
  * 서브모듈 고정을 올리고 다시 생성한다.
* **하지 않은 것**: `cvtps2pi`(`MMX_CVT_F2I`)는 호스트 MXCSR을 따른다. 게임에는 없고, 호스트 MXCSR도 기본이 nearest이므로 그대로 둔다.

# Design: modelling MXCSR, and rounding in SSE integer conversions (issue #48)

## 1. Requirements

* While the demo runs, `[recomp] untranslated instruction at 0015F0F1: stmxcsr dword ptr [0x265150]` is printed. That site is title code that really runs.
* The list of unlifted instructions (`gen/jsrf_us/recomp-summary/summary.json`, 35 kinds) looks mostly like data read as code (**inferred**). This task handles the one that runs, `stmxcsr`. Classifying the rest is a separate task.

## 2. Findings

* **Confirmed** (lifted code): `sub_0015F0F0` (cdecl, four arguments) does the following.
  1. `stmxcsr [0x265150]` stores MXCSR.
  2. It tests bits 13–14 of the stored value (rounding control, RC) with `test ah, 0x60`.
  3. If RC is not 0 (nearest), it returns `0x8000FFFF` (E_UNEXPECTED). If RC is 0, it checks its arguments and does its work.
* The function is not in the XDK symbol database (title code or an unidentified library, **unresolved**). It is called from `0x0015F3A7` and `0x0015F878`.
* Today `stmxcsr` stores nothing. So the check reads whatever 0x265150 held (apparently 0) and happens to go the right way (**inferred**). That is luck.
* The title has no `ldmxcsr`, so the guest MXCSR keeps its reset value 0x1F80 (all exceptions masked, RC = nearest).
* **A bug of the same family**: the lifter translates `cvtss2si`/`cvtsd2si` as a C `(int32_t)` cast, which truncates. The hardware rounds by the MXCSR RC (nearest-even by default). The title has 6 `cvtss2si` sites and 4 `cvttss2si` sites.
  * Casting an out-of-range value is undefined behavior in C. The hardware returns the integer indefinite (0x80000000).

## 3. Design (xboxrecomp fork, `fix/mxcsr` → `rejsrf`; added to upstream PR #198)

* **Guest MXCSR**: handled like the x87 control word (`g_fp_control_word`).
  * New: `RECOMP_TLS uint32_t g_mxcsr`, reset value 0x1F80. It is thread state, so it is TLS.
  * The host MXCSR is not changed, just as x87 `fldcw` never reaches the host.
* **Lifter**:
  * `stmxcsr m32` becomes `MEM32(m) = g_mxcsr`.
  * `ldmxcsr m32` becomes `g_mxcsr = MEM32(m)`.
  * Neither changes EFLAGS (`_EFLAGS_PRESERVE`).
* **Integer conversions**: new `recomp_cvt_si32(value, mxcsr, truncate)`.
  * `cvtss2si`/`cvtsd2si` round by `g_mxcsr`'s RC. The encoding is the x87 one, so `recomp_frndint` is reused.
  * `cvttss2si`/`cvttsd2si` truncate.
  * NaN, infinities and out-of-range values give 0x80000000.
* **Exception flags** (MXCSR bits 0–5) are not modelled; the stored value has them clear, as the x87 status word's exception byte is not modelled either.
* **reJSRF**:
  * `rexbox_recomp` (`recomp_abi.c`) defines `g_mxcsr` and sets it to 0x1F80 when it initializes a thread.
  * The submodule pin moves up, and the code is regenerated.
* **Not done**: `cvtps2pi` (`MMX_CVT_F2I`) follows the host MXCSR. The title has none, and the host MXCSR also defaults to nearest, so it stays.

## 4. Verification

The table in the Korean section applies: xboxrecomp unit tests pass (new ones included); after regeneration `stmxcsr` is gone from the unimplemented list; the demo runs without the `untranslated instruction` warning; the regression tools have 0 failures and the logo frame dumps match the baseline.
