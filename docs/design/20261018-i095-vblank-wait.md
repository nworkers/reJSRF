# 설계: VBlank 대기 켜기/끄기 (issue #95)

## 1. 목표

* 설정 메뉴 Graphics 탭에 "VBlank wait" 켜기/끄기를 둔다. 끄면 게임이 Xbox의 60 Hz 가상 수직 귀선을 기다리지 않고, 호스트가 그릴 수 있는 만큼 빨리 돈다.
* 용도는 벤치마크(성능 비교)다. 게임 진행이 프레임 단위라 끄면 게임 속도도 빨라진다.

## 2. 현재 구조(**확인됨**)

* `d3d8_vblank`의 가상 시계(게스트 refresh, 기본 60 Hz)가 게임 속도를 정한다.
  * `D3DDevice_BlockUntilVerticalBlank`는 다음 tick까지 잔다.
  * `D3DDevice_Swap`은 present interval만큼 tick을 기다린다.
  * 시계의 tick 수(`VerticalBlankCount`)와 래스터 위치도 게스트에게 보인다.
* 처음에는 대기만 건너뛰는 방식을 시험했다(시계는 60 Hz 그대로). 그러자 데모 중 1000프레임 구간마다 약 6초짜리 멈춤이 생겨 평균이 60~100 fps에 머물렀다. 시계 수가 바뀌기를 기다리는 게스트 코드가 있는 것으로 보인다(**추정**).

## 3. 설계

* 끄면 시계 자체를 10 kHz로 돌린다. 대기는 그대로 하지만 한 번에 약 0.1 ms뿐이고, 시계 수를 보는 코드도 수가 바뀌는 것을 본다.
* 켜고 끌 때 시계를 다시 맞춘다(`Retime`). 현재 tick 수를 유지한 채 기준점과 주기만 바꾼다. 수가 뒤로 가면, present가 interval을 채울 때까지 그 차이만큼 잠들기 때문이다.
* 끈 동안은 호스트 vsync에 시계 위상을 맞추는 일(`AlignVerticalBlank`)을 하지 않는다.
* 공개 API: `DisplayDefaults.vblank_wait`, `VerticalBlankWaitEnabled`/`SetVerticalBlankWaitEnabled`(`d3d8_display.h`). 실행 중 바꾸면 바로 적용된다.
* 설정: `rejsrf.ini`의 `[Graphics]`에 `VBlankWait = true|false`(기본 true). 메뉴의 VSync 아래에 체크박스와 설명을 둔다.

## 4. 하지 않는 것

* 게임 속도는 그대로 두고 프레임만 늘리기(보간, 논리와 그리기 분리). 게임 논리가 프레임 단위라 이 설정으로는 할 수 없다.

# Design: VBlank wait on/off (issue #95)

## 1. Goal

* A "VBlank wait" on/off in the settings menu's Graphics tab. Off, the game no longer waits for the Xbox's 60 Hz virtual vertical blank and runs as fast as the host draws.
* It is meant for benchmarks. Game logic advances per frame, so the game also speeds up.

## 2. Current structure (**confirmed**)

* The virtual clock in `d3d8_vblank` (the guest's refresh, 60 Hz by default) sets the game's speed.
  * `D3DDevice_BlockUntilVerticalBlank` sleeps until the next tick.
  * `D3DDevice_Swap` waits out the present interval in ticks.
  * The guest also sees the tick count (`VerticalBlankCount`) and the raster position.
* Skipping only the waits, with the clock left at 60 Hz, was tried first. The demo then stalled for about 6 s in every 1000-frame window and averaged 60-100 fps; some guest code apparently waits for the count to change (**inferred**).

## 3. Design

* Off, the clock itself runs at 10 kHz. The waits still happen but last about 0.1 ms, and code that watches the count sees it move.
* A switch retimes the clock (`Retime`), keeping the current tick count and changing only the base and the period. A count that went backwards would make a present sleep out the difference before its interval is met.
* While off, the clock is not aligned to host vsync (`AlignVerticalBlank`).
* Public API: `DisplayDefaults.vblank_wait` and `VerticalBlankWaitEnabled`/`SetVerticalBlankWaitEnabled` (`d3d8_display.h`); a change while running applies at once.
* Settings: `VBlankWait = true|false` in `rejsrf.ini`'s `[Graphics]` (default true); a checkbox with a tooltip under VSync in the menu.

## 4. Not done

* More frames at the same game speed (interpolation, or splitting logic from drawing). Game logic advances per frame, so this setting cannot do it.
