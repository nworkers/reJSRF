# 설계: 호스트 vsync와 가상 vblank 시계의 위상 맞춤 (issue #82)

관련: [i023 고정 기능 그리기 §4 수직 동기](20261012-i023-d3d8-fixed-function-draw.md)

## 1. 문제

화면이 찢어진다(tearing). 테두리 없는 전체화면에서 특히 잘 보인다.

* 지금은 호스트 swap interval이 0이다(`display_sdl.cpp`). `Swap`의 속도는 HLE의 가상 60 Hz vblank 시계(`d3d8_vblank.cpp`)만 맞춘다.
* 프레임 수는 맞지만 버퍼 교체가 모니터의 주사 도중 아무 때나 일어나서 찢어진다.
* 창 모드는 DWM 합성 덕분에 덜 보이고, 전체화면은 DWM을 거치지 않고 바로 표시돼서 잘 보인다.
* i023이 vsync를 끈 이유는 두 가지다(**유지할 것**):
  1. 게임 속도가 모니터 주사율에 묶이지 않게 한다.
  2. 숨긴 창에서 vblank를 기다리면 일부 드라이버가 멈춘다.

## 2. 설계

### 2.1 보이는 창에서 호스트 vsync

* `DisplayConfig.vsync`: `kOff`, `kOn`, `kAdaptive`.
  * `kAdaptive`: swap interval -1(늦은 프레임만 찢어짐을 허용). 드라이버가 거부하면 1로 둔다.
  * `kOn`: 1. `kOff`: 0.
  * 숨긴 창(`hidden`)은 언제나 0이다.
* `DisplayInfo`
  * `swap_interval`: 실제로 적용된 값(0, 1, -1).
  * `refresh_hz`: 창이 있는 모니터의 주사율(모르면 0). 창을 만들 때, 크기가 바뀔 때, 창이 다른 모니터로 갈 때 다시 읽는다.
* `REXBOX_VSYNC=off|on|adaptive`(기본 `adaptive`). D3D8 HLE가 읽어 `DisplayConfig`로 넘기고, 적용 결과를 `[d3d8] display ...` 줄에 함께 적는다.
* 게임 속도는 여전히 가상 시계가 정한다. vsync는 swap을 다음 귀선까지 늦출 뿐이다.

### 2.2 가상 시계를 호스트 귀선에 맞추기

vsync만 켜면 가상 시계(60.000 Hz)와 모니터(예: 59.94 Hz)의 작은 차이가 쌓인다. 그러면 수십 초마다 swap이 한 귀선을 더 기다리는 끊김이 생긴다.

* 조건: `swap_interval != 0`이고, `|refresh_hz − 게스트 주사율| ≤ 1 Hz`일 때.
* present에서 swap(`platform::PresentDisplay`)에 걸린 시간을 잰다. **swap이 1 ms 이상 막혔으면**, 그 반환 시각을 호스트 귀선 시각으로 본다.
* `AlignVerticalBlank(t)`: 다음 tick이 `t + 주기 − 앞섬`에 오도록 가상 시계의 기준 시각을 옮긴다.
  * 앞섬은 3 ms다. `Swap`의 대기가 귀선보다 조금 일찍 깨야, blit과 swap 요청이 그 귀선 안에 들어간다. 늦게 깨면 한 귀선을 통째로 놓친다.
  * 현재 tick 번호는 바뀌지 않게 옮긴다. 그래서 `VerticalBlankCount`는 계속 단조 증가한다.
* swap이 막히지 않았으면 맞추지 않는다. 드라이버가 vsync를 무시하거나 프레임을 쌓아 두는 경우다. 이렇게 해야 잘못된 시각을 따라가 게임이 빨라지는 일이 없다.
* 결과: 60 Hz 근처 모니터에서는 매 프레임이 같은 귀선에 맞춰 나온다. 게임 속도는 모니터 주사율을 따른다(59.94 Hz면 0.1% 느림, 허용 범위). 다른 주사율(120/144 Hz 등)에서는 가상 시계가 속도를 정하고, vsync는 찢어짐만 막는다.

### 2.3 하지 않는 것

* 고주사율 모니터의 프레임 간격 불균일(judder) 보정, 프레임 보간.
* 120 Hz처럼 게스트 주사율의 정수배인 모니터에 맞추는 것.

## 3. 검증

* Release·Debug 빌드, 회귀 도구 세 개.
* 숨긴 창 데모: 배율 1 프레임 BMP가 변경 전과 같다(숨긴 창은 vsync 0, 맞춤 없음).
* 사용자 플레이: 창·전체화면에서 찢어짐이 없는지, FPS가 60 근처로 안정적인지, 끊김이 없는지. `REXBOX_VSYNC=off`로 예전 동작이 나오는지.

# Design: host vsync and locking the virtual vblank clock's phase to it (issue #82)

Related: [i023 fixed-function draw §4 vertical sync](20261012-i023-d3d8-fixed-function-draw.md)

## 1. Problem

The picture tears, most visibly in borderless fullscreen.

* The host swap interval is 0 (`display_sdl.cpp`). Only the HLE's virtual 60 Hz vblank clock (`d3d8_vblank.cpp`) paces `Swap`.
* The frame count is right, but buffer swaps happen anywhere in the monitor's scan-out, so the picture tears.
* Windowed mode hides it partly through DWM composition; fullscreen bypasses DWM and shows it.
* i023 turned vsync off for two reasons (**kept**):
  1. The game's speed must not depend on the monitor's refresh.
  2. Waiting for a hidden window's blank can block on some drivers.

## 2. Design

### 2.1 Host vsync for visible windows

* `DisplayConfig.vsync`: `kOff`, `kOn`, `kAdaptive`.
  * `kAdaptive`: swap interval -1 (only late frames may tear). If the driver refuses it, 1.
  * `kOn`: 1. `kOff`: 0.
  * A hidden window always gets 0.
* `DisplayInfo`
  * `swap_interval`: the value actually applied (0, 1 or -1).
  * `refresh_hz`: the refresh of the monitor showing the window (0 if unknown). Read again when the window is created, resized, or moved to another monitor.
* `REXBOX_VSYNC=off|on|adaptive` (default `adaptive`). The D3D8 HLE reads it, passes it in `DisplayConfig`, and adds the result to the `[d3d8] display ...` line.
* The virtual clock still sets the game's speed; vsync only delays a swap to the next blank.

### 2.2 Locking the virtual clock to the host's blank

With vsync alone, the small difference between the virtual clock (60.000 Hz) and the monitor (59.94 Hz, say) accumulates, and every few tens of seconds a swap waits one extra blank, which shows as a hitch.

* Condition: `swap_interval != 0` and `|refresh_hz − the guest refresh| ≤ 1 Hz`.
* The present times the swap (`platform::PresentDisplay`). **When the swap blocked for 1 ms or more**, its return time is taken as the host's blank.
* `AlignVerticalBlank(t)`: moves the virtual clock's base so the next tick falls at `t + period − lead`.
  * The lead is 3 ms. `Swap`'s wait must wake a little before the blank, so the blit and the swap request make that blank; waking late misses a whole blank.
  * The move keeps the current tick number, so `VerticalBlankCount` stays monotonic.
* A swap that did not block does not align: the driver ignores vsync or queues frames. Skipping it keeps the clock from following a wrong time and speeding the game up.
* Result: on monitors near 60 Hz every frame lands on the same blank, and the game runs at the monitor's rate (0.1% slower at 59.94 Hz, acceptable). At other refreshes (120/144 Hz and so on) the virtual clock sets the speed and vsync only prevents tearing.

### 2.3 Not done

* Correcting uneven frame spacing (judder) on high-refresh monitors, or frame interpolation.
* Locking to monitors at an integer multiple of the guest refresh, such as 120 Hz.

## 3. Verification

* Release and Debug builds, the three regression tools.
* Hidden-window demo: scale 1 frame BMPs identical to before (hidden windows have vsync 0 and no alignment).
* User play: no tearing windowed or fullscreen, FPS steady near 60, no hitches; `REXBOX_VSYNC=off` gives the old behavior.
