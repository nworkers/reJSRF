# 설계: xboxrecomp를 upstream v0.16.0 기반으로, 스텁 보고는 upstream 방식으로 (issue #115)

상태: **구현됨**(사용자 결정). 작업 지시: [20261023-i115](../work-orders/20261023-i115-xboxrecomp-v0.16.md) · 작업 로그: [20261023-i115](../work-logs/20261023-i115-xboxrecomp-v0.16.md)

선행: [i093 xboxrecomp v0.15.0](20261020-i093-xboxrecomp-v0.15.md), [i055 미해결 스텁](20261014-i055-unresolved-stubs.md), [분석 unresolved-stubs](../analysis/unresolved-stubs.md), [분석 function-discovery](../analysis/function-discovery.md)

## 1. 요구

* xboxrecomp를 최신 upstream(v0.16.0 "Small Print", 2026-10-20, `f0f8a461`)으로 옮긴다.
* fork 전용 커밋 `5aae5df`(미해결 스텁을 rexbox로 보고하는 `RECOMP_STUB_REPORT`)는 뺀다. upstream의 `RECOMP_STUB_LOG`를 쓰고, **Debug 빌드일 때만** 앱이 이 값을 1로 넣는다(사용자 결정).

## 2. 확인한 것 (검토, 2026-10-23)

* **fork 구성**: `rejsrf`(`5aae5df`)는 v0.15.0 위에 커밋 8개다. 그중 #93의 disasm 수정 셋(`adc827c7`, `49534721`, `3a1afff0`)은 PR #236으로 v0.16.0에 **같은 커밋 그대로** 들어갔다. fork에만 남는 것은 다섯이다.

| 커밋 | 내용 | 이번 작업 |
|---|---|---|
| `44cb0392` | 함수마다 게스트 메모리 기준값을 한 번만 읽기(#44, 효과 약 1%) | 유지 |
| `56b73d9f`, `716547cc` | XMM 도우미 SSE2 intrinsic(`REXBOX_RECOMP_XMM_SSE2`, 기본 꺼짐, fork 전용) | 유지 |
| `16a4a0da` | C2를 지울 때 잘리는 상수 캐스트를 없앰(C4310) | 유지 |
| `5aae5df` | 스텁이 `recomp_unresolved_stub_log(va)`를 부름(`RECOMP_STUB_REPORT`) | **되돌림** |

* **v0.16.0의 변경**: #236(우리 수정), #237(xboxrecomp 자체 커널의 POSIX 파일, reJSRF는 쓰지 않음), #238(16비트 push/pop의 esp, JSRF 코드에 해당 명령 없음), #239(패딩 뒤 함수 발견).
* **ABI 헤더**: `templates/runtime/recomp_types.h`는 v0.15.0과 v0.16.0이 같고, fork 커밋을 얹은 결과도 지금 fork와 바이트 단위로 같다. rexbox 런타임은 바뀌지 않는다.
* **시험**: fork 전용 다섯 커밋을 v0.16.0 위에 충돌 없이 올렸고, upstream 테스트 794개가 통과했다(116개 건너뜀, `pefile`이 필요한 `tools/fusion` 제외).
* **#239가 JSRF에 미치는 영향**(미국판, 디스어셈블 단계만): 함수 9,481개 → 9,297개.
  * 빠진 198개는 v0.15에서 `gap_prologue` 178개와 `tail_jump_alias` 20개로 잡힌 것이다. 모두 앞 함수의 본문 안에 들어갔고, 직접 호출되는 것은 없다.
  * 이미지 안에 포인터로 나오는 것은 14개이고, 대부분 바로 뒤의 switch 점프 표 항목이다. `0x182444`(SEH 필터 조각으로 보임)는 `0x182437`의 별칭이 되었다.
  * 새로 생긴 함수 14개, 시작은 같고 끝이 달라진 함수 2,097개.
  * 이름으로 쓰는 225개(seed, 디컴파일 함수, 추가 심볼, 프로파일)는 모두 남는다.
* **스텁 보고**: upstream은 생성된 `recomp_stubs_unresolved.c`의 `RECOMP_STUB_HIT`가 스텁마다 처음 한 번 `[STUB] unresolved 0x<va> reached, return 0x<ret> esp 0x<esp>`를 stderr에 쓴다. 단 환경 변수 `RECOMP_STUB_LOG`가 비어 있지 않고 `0`이 아닐 때만이다. 첫 스텁이 불릴 때 한 번 읽는다(`recomp_stub_log_on`). `5aae5df`를 빼도 rexbox의 `RECOMP_STUB_REPORT` 정의는 무시될 뿐이고, `recomp_unresolved_stub_log`는 쓰이지 않게 된다(빌드는 그대로).

## 3. 방안

| 방안 | 내용 | 판단 |
|---|---|---|
| **A'. fork `rejsrf`에 v0.16.0 병합, `5aae5df` 되돌리기** | merge 커밋 하나와 revert 커밋 하나. #236 커밋이 같아 충돌이 없고 force push가 필요 없다 | **채택**(사용자 결정) |
| B. fork 없이 upstream v0.16.0 | 메모리 기준값·XMM 옵션·C4310 수정이 사라진다 | 나중에 rexbox의 xboxrecomp 갱신과 함께 다시 본다 |

### 3.1 Debug 빌드의 스텁 보고

* 앱(`src/app/main.cpp`)이 게임 스레드를 시작하기 전, Debug 빌드(`NDEBUG` 미정의)에서 `RECOMP_STUB_LOG`가 **설정돼 있지 않을 때만** `1`로 넣는다. 사용자가 준 값(예: `0`)은 그대로 둔다. Release 빌드는 넣지 않는다. 필요하면 사용자가 직접 `RECOMP_STUB_LOG=1`을 준다.
* 첫 스텁 호출 전에 넣으면 되므로(§2), 게스트 진입 전이면 충분하다.
* 환경 변수 설정은 Windows `_putenv_s`, 그 밖에는 `setenv`다. rexbox에 이런 도우미가 없고, 같은 파일이 이미 플랫폼 매크로로 빌드 식별을 만들므로 앱 안에 둔다.
* rexbox의 `RECOMP_STUB_REPORT` 정의와 `recomp_unresolved_stub_log`는 upstream만 쓰는 지금 필요 없다. 이 저장소에서 rexbox를 고치지 않으므로(AGENTS.md) 정리는 rexbox 저장소의 후속 일로 남긴다.

### 3.2 재생성

* 두 변형(미국판, 일본판)을 다시 생성한다. ABI 헤더가 같아 CMake의 해시 확인은 통과하지만, 함수 경계가 바뀌어 생성 코드가 달라진다.
* 일본판 지문 확인(`variant_fingerprints.py`)은 XBE 바이트로 하므로 바뀌지 않는다.
* 실행에서 간접 호출이 대상을 찾지 못하면(`indirect call ... has no target`) `find_pointer_targets.py`로 seed를 더한다.

## 4. 범위 밖

* 방안 B(fork 없애기)와 rexbox 안의 xboxrecomp 고정(v0.15.0) 갱신: rexbox 저장소 일.
* 남은 fork 커밋의 upstream PR: 사용자가 정할 때까지 보류(기존 결정).

# Design: xboxrecomp on upstream v0.16.0, stub logging the upstream way (issue #115)

Status: **implemented** (the user's decision). Work order: [20261023-i115](../work-orders/20261023-i115-xboxrecomp-v0.16.md) · Work log: [20261023-i115](../work-logs/20261023-i115-xboxrecomp-v0.16.md)

Before: [i093 xboxrecomp v0.15.0](20261020-i093-xboxrecomp-v0.15.md), [i055 unresolved stubs](20261014-i055-unresolved-stubs.md), [analysis unresolved-stubs](../analysis/unresolved-stubs.md), [analysis function-discovery](../analysis/function-discovery.md)

## 1. Requirement

* Move xboxrecomp to the latest upstream (v0.16.0 "Small Print", 2026-10-20, `f0f8a461`).
* Drop the fork-only commit `5aae5df` (`RECOMP_STUB_REPORT`, reporting unresolved stubs through rexbox) and use upstream's `RECOMP_STUB_LOG`, which the app sets to 1 **in Debug builds only** (the user's decision).

## 2. What was established (the review, 2026-10-23)

* **Fork contents**: `rejsrf` (`5aae5df`) is eight commits on v0.15.0. #93's three disasm fixes (`adc827c7`, `49534721`, `3a1afff0`) went into v0.16.0 as PR #236 **as the same commits**. Five remain fork-only:

| Commit | What | Here |
|---|---|---|
| `44cb0392` | read the guest memory base once per function (#44, about 1%) | kept |
| `56b73d9f`, `716547cc` | SSE2 intrinsics for the XMM helpers (`REXBOX_RECOMP_XMM_SSE2`, off by default, fork-only) | kept |
| `16a4a0da` | clear C2 without a truncating constant cast (C4310) | kept |
| `5aae5df` | stubs call `recomp_unresolved_stub_log(va)` (`RECOMP_STUB_REPORT`) | **reverted** |

* **v0.16.0's changes**: #236 (ours), #237 (POSIX files in xboxrecomp's own kernel, unused by reJSRF), #238 (esp for 16-bit push/pop; JSRF has no such instruction), #239 (functions past padding).
* **ABI header**: `templates/runtime/recomp_types.h` is the same in v0.15.0 and v0.16.0, and with the fork commits on top it equals today's fork byte for byte; the rexbox runtime does not change.
* **Trial**: the five fork-only commits went onto v0.16.0 without conflicts, and 794 upstream tests passed (116 skipped; `tools/fusion`, which needs `pefile`, left out).
* **#239 on JSRF** (US build, the disassembly stage only): 9,481 → 9,297 functions.
  * The 198 that left were v0.15's 178 `gap_prologue` and 20 `tail_jump_alias` starts; all now lie inside the preceding body, and none is called directly.
  * 14 appear as pointers in the image, mostly as entries of the switch jump table right after them; `0x182444` (apparently an SEH filter fragment) became an alias of `0x182437`.
  * 14 functions are new; 2,097 keep their start with another end.
  * All 225 named addresses (seeds, decompiled functions, extra symbols, the profile) remain.
* **Stub logging**: upstream's `RECOMP_STUB_HIT` in the generated `recomp_stubs_unresolved.c` writes `[STUB] unresolved 0x<va> reached, return 0x<ret> esp 0x<esp>` to stderr the first time each stub runs, but only when the environment variable `RECOMP_STUB_LOG` is set, non-empty and not `0`; it is read once, when the first stub runs (`recomp_stub_log_on`). Without `5aae5df`, rexbox's `RECOMP_STUB_REPORT` definition is merely ignored and `recomp_unresolved_stub_log` goes unused (the build is unchanged).

### 3.1 Stub logging in Debug builds

* Before the game thread starts, the app (`src/app/main.cpp`) sets `RECOMP_STUB_LOG=1` in Debug builds (`NDEBUG` undefined) **only when it is not set**; a value the user gives (`0`, say) stays. Release builds set nothing; users who want it there give `RECOMP_STUB_LOG=1` themselves.
* It only has to be set before the first stub runs (§2), so before the guest entry is enough.
* Setting it is `_putenv_s` on Windows and `setenv` elsewhere. rexbox has no such helper, and the same file already builds its build identity from platform macros, so it stays in the app.
* rexbox's `RECOMP_STUB_REPORT` definition and `recomp_unresolved_stub_log` are unneeded now that only upstream's path is used. This repository does not edit rexbox (AGENTS.md), so tidying them is a follow-up in the rexbox repository.

### 3.2 Regeneration

* Both variants (US, Japanese) are regenerated. The ABI header is the same, so CMake's hash check passes, but the function boundaries move and the generated code changes.
* The Japanese fingerprint check (`variant_fingerprints.py`) works on XBE bytes and does not change.
* Where a run finds an indirect call with no target (`indirect call ... has no target`), `find_pointer_targets.py` adds seeds.

## 4. Out of scope

* Upstream PRs for the remaining fork commits: held until the user decides (the standing decision).
