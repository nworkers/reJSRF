## reJSRF v0.0.50

이전 릴리스 **v0.0.49** 이후의 변경입니다(issue #115). **재컴파일 도구 xboxrecomp를 upstream v0.16.0 기반으로 옮겼습니다.** 미해결 스텁 보고는 upstream 방식으로 바꾸고, Debug 빌드에서만 기본으로 켜집니다.

### 바뀐 것

* **xboxrecomp**([설계 i115](../design/20261023-i115-xboxrecomp-v0.16.md))
  * fork `rejsrf`(`6acdc0c`)는 upstream v0.16.0(`f0f8a46`)을 병합한 것이다.
  * v0.16.0에는 우리가 낸 #93의 디스어셈블러 수정이 PR #236으로 들어 있다.
  * fork에만 남은 것은 메모리 기준값(#44), XMM SSE2 옵션(기본 꺼짐), C4310 수정이다.
  * fork 전용 스텁 보고(`5aae5df`)는 되돌렸다.
  * ABI 헤더는 바뀌지 않았다. 이전 핀은 fork 브랜치 `rejsrf-v0.15`에 있다.
* **미해결 스텁 보고**
  * 디스어셈블러가 놓친 주소가 실행되면, upstream의 생성 코드가 스텁마다 처음 한 번 `[STUB] unresolved 0x<주소> reached, return … esp …`를 쓴다. 환경 변수 `RECOMP_STUB_LOG`가 있을 때만이다.
  * 앱은 **Debug 빌드에서만** 이 값을 1로 넣는다(이미 설정돼 있으면 그대로).
  * Release에서는 `RECOMP_STUB_LOG=1`을 직접 준다.
* **생성 코드**: v0.16.0의 패딩 뒤 함수 판단(#239)으로 잘못 나뉘던 시작 198개가 앞 함수 본문에 합쳐졌다. 함수는 9,481개에서 9,297개, 미해결 스텁은 28개에서 19개가 되었다. 빌드하는 쪽은 `git submodule update`와 `scripts/recomp/regenerate.py`를 다시 돌려야 한다.

## reJSRF v0.0.50 (English)

Changes since **v0.0.49** (issue #115). **The xboxrecomp recompiler moves onto upstream v0.16.0.** Unresolved-stub reporting now works the upstream way, on by default in Debug builds only.

Resolved issue: #115, xboxrecomp v0.16.0; commits `46bb848` (design) and `6125066` (fork merge, stub reporting, regeneration, documents).

Changes:
* **xboxrecomp** ([design i115](../design/20261023-i115-xboxrecomp-v0.16.md))
  * The fork's `rejsrf` (`6acdc0c`) has upstream v0.16.0 (`f0f8a46`) merged in.
  * v0.16.0 carries our #93 disassembler fixes as PR #236.
  * Fork-only are the memory base (#44), the XMM SSE2 option (off by default) and the C4310 fix.
  * The fork-only stub report (`5aae5df`) was reverted.
  * The ABI header is unchanged; the previous pin stays on the fork branch `rejsrf-v0.15`.
* **Unresolved-stub reporting**
  * When an address the disassembler missed runs, upstream's generated code writes `[STUB] unresolved 0x<va> reached, return … esp …` the first time each stub runs, if the environment variable `RECOMP_STUB_LOG` is set.
  * The app sets it to 1 **in Debug builds only** (a value already set stays).
  * In Release, give `RECOMP_STUB_LOG=1` yourself.
* **Generated code**: v0.16.0's judgement of functions past padding (#239) folds 198 wrongly split starts into their bodies; functions go from 9,481 to 9,297 and unresolved stubs from 28 to 19. Builders must run `git submodule update` and `scripts/recomp/regenerate.py` again.

Verified: upstream tests, 794 passed. Regeneration (US and Japanese) gives both builds the same counts and stub list, and the Japanese fingerprint check passes; the new stub `0x115FE5` is a false branch from a jump table read as a function and never runs. Win32 x86 Release (US and Japanese) and Debug (US) with zero warnings; rexbox probes 94/55/220 with 0 failures, decomp check 129 and d3d8 check 14,018 cases with 0 differences, `check_hle_pops.py` 0 mismatches. US and Japanese demo frames 300-1800 equal the previous builds byte for byte, and no stub or indirect-call miss ran in 3,600 frames. Debug sets `RECOMP_STUB_LOG=1`, a given `0` stays, Release sets nothing. User: approved the merge.
