## reJSRF v0.0.22

이전 릴리스 **v0.0.21** 이후의 변경입니다(issue #51). **링크한 GL 프로그램을 디스크에 캐시해, 두 번째 실행부터 셰이더 컴파일로 생기던 끊김이 사라졌습니다.** 데모 시작의 가장 긴 프레임은 약 2.0초에서 0.9~1.1초로 줄었습니다.

### 바뀐 것

* **프로그램 바이너리 캐시.** 링크한 프로그램을 드라이버의 바이너리로 `cache\shaders\`에 저장하고, 다음 실행에서 컴파일 대신 씁니다.
  * 드라이버 식별과 두 셰이더 소스가 완전히 같을 때만 씁니다.
  * 드라이버가 거부하면 컴파일하고 항목을 다시 씁니다.
  * 위치는 `REXBOX_SHADER_CACHE=<폴더>`로 바꾸고, `REXBOX_SHADER_CACHE=0`으로 끕니다. `cache/`는 gitignore입니다.
* **측정**(Intel HD Graphics 620):
  * 데모의 프로그램 57개가 약 2.4초(컴파일) 대신 약 0.13초(캐시)에 만들어집니다.
  * 첫 실행은 지금처럼 컴파일합니다.
* **진단.** `REXBOX_D3D8_PROFILE`가 구간마다 만든 프로그램 수와 시간, 가장 긴 프레임, 33.4 ms를 넘은 프레임 수를 냅니다.
* **남은 것.**
  * 데모 시작의 남은 약 1초는 처음 쓰는 텍스처의 디코드·업로드로 봅니다(추정).
  * 주기적인 83~100 ms 프레임도 아직 남아 있습니다.

## reJSRF v0.0.22 (English)

Changes since **v0.0.21** (issue #51). **Linked GL programs are cached on disk, so from the second run on, shader compilation no longer stalls the game.** The longest frame at the start of the demo fell from about 2.0 s to 0.9–1.1 s.

Resolved issue: #51, stutter from compiling GL programs on first use (a program binary cache), commit `6ec86a1`.

Changes:
* **Program binary cache:** a linked program is stored under `cache\shaders\` as the driver's binary and used instead of compiling on the next run.
  * It is used only when the driver identity and both shader sources match exactly.
  * A rejected binary is compiled again and its entry rewritten.
  * `REXBOX_SHADER_CACHE=<folder>` moves the cache and `REXBOX_SHADER_CACHE=0` turns it off; `cache/` is gitignored.
* **Measurement** (Intel HD Graphics 620):
  * The demo's 57 programs take about 0.13 s from the cache instead of about 2.4 s compiled.
  * The first run still compiles.
* **Diagnostics:** `REXBOX_D3D8_PROFILE` reports programs made per window, the longest frame, and frames over 33.4 ms.
* **Still open:**
  * The remaining stall of about a second at the start of the demo is taken to be textures decoded and uploaded on first use (inferred).
  * Periodic 83–100 ms frames also remain.

Verified on Win32 x86 Debug and Release:
* zero build warnings
* kernel probe 56/56, D3D8 probe 116/116, DSOUND probe 48/48
* d3d8 check 14,018 cases with 0 differences; decomp check 6/6
* all 57 programs made from the cache in a second run; two damaged entries recompiled and rewritten
* CI on the pull request
