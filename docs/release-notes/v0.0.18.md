## reJSRF v0.0.18 (English)

Changes since **v0.0.17** (issue #44). **The lifted title code's XMM (SSE) operations are faster, cutting the CPU time per frame of the opening 3D demo by about 12%.** The picture is the same as v0.0.15.

Resolved issue: #44, xboxrecomp code generation (SSE2 intrinsics for the XMM helpers, the memory base read once per function), commits `c5e2459`, `5f47d1e`, `9e01efa`.

Changes:
* **XMM helpers:** the xboxrecomp fork (`rejsrf` `541b554`) implements its XMM helpers with SSE2 intrinsics (`movss`, `mulps`, `shufps` and others).
  * The old lane-wise C wrote a stack temporary in parts and read it back 16 bytes wide, a failed store-to-load forward.
  * The results are bit-identical to the old C (checked by a test).
  * Because upstream deliberately writes these helpers as lane-wise C, this change stays on our fork and is not proposed upstream.
* **Memory base:** translated functions read the guest memory base once on entry. This change is held as a candidate for upstream.
* **Measurement:** presenting-thread CPU time (ms per frame, mean of three alternating runs).
  * 483-draw window: 15.24 → 14.17
  * the other windows: 13–15% lower
* **Remaining candidates:** guest registers in locals could save at most about 7% of total CPU, a per-site indirect-call cache about 1%. Neither was done.

Verified:
* xboxrecomp: 594 unit tests pass; `test_xmm_intrinsics` passes with cl and catches a planted bug.
* Win32 x86 Debug and Release: regeneration and builds with zero warnings; kernel probe 56/56, D3D8 probe 116/116, DSOUND probe 48/48; d3d8 check 14,018 cases with 0 differences; decomp check 6/6; 0 pop mismatches.
* Frames 2,800, 3,000, 3,200 and 3,400 identical to v0.0.15 pixel for pixel.
* CI on the pull request.
