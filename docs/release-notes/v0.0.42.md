## reJSRF v0.0.42 (English)

Changes since **v0.0.41** (issue #100). **A hang in play (the SVM "release all" loop of the wxCi file path) is fixed.**

Resolved issue: #100, the SVM "release all" loop never ending at TIME_CRITICAL with no lock held; commit `bfbd343`.

Changes:
* **SVM "release all" loop** ([design i100](../design/20261019-i100-svm-unlock-all.md))
  * The game's `0x001437B0` repeats "release the SVM lock while TIME_CRITICAL" (single-core reasoning). On the host some orders leave a thread TIME_CRITICAL holding no lock, and the loop never ended (the place of i068 and i091; thread 2 of the stall report).
  * The adapter (`src/game/jsrf/decomp/adxm_lock.c`) replaces the function: it releases only this thread's depth from i091 and returns that count, and if still TIME_CRITICAL lowers the thread to its own priority with one report (`[adxm lock] a thread was TIME_CRITICAL holding no lock; ... (issue #100)`).
  * Builders must rerun `scripts/recomp/regenerate.py`.

Verified: Win32 x86 Debug and Release with zero warnings; D3D8 probe 163/163; d3d8 check 14,018 cases with 0 differences; decomp check 129 cases with 0 differences. A 120 s demo at 21:9 with no fault, stall or report (the demo does run this path). User: play.
