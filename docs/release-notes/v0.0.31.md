## reJSRF v0.0.31 (English)

Changes since **v0.0.30** (issue #73). **The title's matrix-stack functions are decompiled, cutting the presenting thread's CPU time in the demo window by about 2 ms per frame.**

Resolved issue: #73, decompile the MMATRIX matrix-stack functions, commits `e9c9ba1` and `ae2bdf5`.

Changes:
* **MMATRIX decompiled:** 21 functions of the title's `MMATRIX` section (a matrix stack: push/pop, translate, rotate, point transforms and more) are rewritten in portable plain C (`src/game/jsrf/decomp/mmatrix.c`).
  * They keep the original order of operations, so the results are bit-identical.
  * They also leave the general registers, the stack and the XMM registers as the originals do.
* **Effect:** over demo frames 2,700–3,300 these functions drew 156 samples instead of 744, about 79% fewer, or about 2 ms per frame.
* **Checker:**
  * `rejsrf_decomp_check` compares XMM registers too, with 129 cases instead of 6.
  * The recomp ABI gained `rexbox_recomp_get_xmm`/`set_xmm`.

Verified:
* Win32 x86 Debug and Release: zero build warnings.
  * decomp check: 129 cases with 0 differences.
  * Probes: kernel 56/56, D3D8 162/162, DSOUND 48/48.
  * d3d8 check: 14,018 cases with 0 differences. HLE pop check: 0 mismatches.
* Behavior: demo frames 1,200, 2,800 and 4,650 look right.
* CI on the pull request.
