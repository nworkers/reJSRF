## reJSRF v0.0.51

이전 릴리스 **v0.0.50** 이후의 변경입니다(issue #117). **xboxrecomp 파이프라인을 이 저장소로 옮기고 rexbox를 v0.0.12에 고정했습니다. rexbox는 이제 lifter를 모릅니다(rexbox #26).**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#117](https://github.com/nworkers/reJSRF/issues/117) | rexbox #26을 따라 xboxrecomp 파이프라인을 이 저장소로 옮김 | `f8294c7` 및 이 릴리스 커밋 |

### 바뀐 것

* **submodule**: `third_party/rexbox`를 v0.0.12(`a018038`, rexbox `main`의 머지 커밋)에 고정한다. #26은 v0.0.11로 머지되었고, v0.0.12는 생성 코드 없는 트리(이 저장소의 CI)에서 앱이 링크되지 않던 v0.0.11의 문제를 고쳤다. rexbox는 xboxrecomp submodule, `REXBOX_XBOXRECOMP_DIR`, `rexbox_check_license`, 재컴파일 스크립트를 지웠다.
* **파이프라인**([설계 i117](../design/20261024-i117-lifter-pipeline.md)): 새 `scripts/recomp/lifter.py`가 이 저장소의 xboxrecomp(fork `rejsrf`)를 실행하고 그 출력을 읽는다. `regenerate.py`, `check_hle_pops.py`, `find_pointer_targets.py`는 이 모듈과 rexbox의 보조 함수(`hle_overrides`, `hle_pops`, `pointer_targets`, `xbe_variant`)를 부른다.
* **CMake**: `REXBOX_XBOXRECOMP_DIR`와 `rexbox_check_license` 호출을 지웠다(`tools/` 포함). rexbox는 lifter ABI의 자기 쪽(`recomp_abi.c`)을 생성 코드 옆의 `recomp_types.h`로 컴파일한다(`rejsrf_recomp_abi`).
* **규칙**: xboxrecomp의 LGPL 파일은 어떤 타깃의 소스 목록이나 include 경로에도 넣지 않는다(AGENTS.md). 검사 코드는 없다.
* **재생성은 필요 없다.** `git submodule update --recursive` 뒤 다시 빌드하면 된다.

## reJSRF v0.0.51 (English)

Changes since **v0.0.50** (issue #117). **The xboxrecomp pipeline moved into this repository, and rexbox is pinned to v0.0.12; rexbox no longer knows the lifter (rexbox #26).**

Resolved issue: #117, moving the xboxrecomp pipeline into this repository, following rexbox #26 (`f8294c7` and this release's commit).

Changes:
* `third_party/rexbox` is pinned to v0.0.12 (`a018038`, the merge commit on rexbox's `main`). #26 was merged as v0.0.11; v0.0.12 fixes v0.0.11's link failure for an application in a tree with no generated code (this repository's CI). rexbox dropped its xboxrecomp submodule, `REXBOX_XBOXRECOMP_DIR`, `rexbox_check_license` and its recompilation scripts.
* The new `scripts/recomp/lifter.py` ([design i117](../design/20261024-i117-lifter-pipeline.md)) runs this repository's xboxrecomp (the fork's `rejsrf`) and reads its output. `regenerate.py`, `check_hle_pops.py` and `find_pointer_targets.py` call it and rexbox's helpers (`hle_overrides`, `hle_pops`, `pointer_targets`, `xbe_variant`).
* CMake no longer sets `REXBOX_XBOXRECOMP_DIR` or calls `rexbox_check_license` (including in `tools/`). rexbox compiles its side of the lifter ABI (`recomp_abi.c`) against the `recomp_types.h` next to the generated code (`rejsrf_recomp_abi`).
* The rule that xboxrecomp's LGPL files never go into any target's source list or include path stays in AGENTS.md; no code checks it.
* **No regeneration is needed:** after `git submodule update --recursive`, rebuild.

Verified:
* Regenerating US and Japanese and comparing with the previous output: the lifted C is byte-identical, and so is the output of `check_hle_pops` (both builds, 0 mismatches) and `find_pointer_targets` (US, 0 candidates).
* Win32 x86 Release (US) builds, and `recomp_abi.c` compiles with 0 warnings.
* The decomp check gives 129 cases and the d3d8 check 14,018 cases, both with 0 differences.
* A 40 s run with a hidden window boots, reaches the warning screen (frame 2000) and keeps its frame loop going, with no stop or fault.

Not verified: gameplay (there is no input script) and the Japanese build.
