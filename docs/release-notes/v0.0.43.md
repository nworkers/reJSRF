## reJSRF v0.0.43

이전 릴리스 **v0.0.42** 이후의 변경입니다(issue #93). **재컴파일 도구를 xboxrecomp v0.15.0으로 올렸습니다.** v0.14.0부터 놓치던 JSRF의 vtable 메서드를 되찾는 수정을 함께 넣었고, upstream에 PR로 냈습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#93](https://github.com/nworkers/reJSRF/issues/93) | xboxrecomp 전환(v0.14.0 보류 → v0.15.0), 표 항목 검사가 버리던 vtable 메서드 복구 | `1967e4c`, `b93a93d` |

### 바뀐 것

* **xboxrecomp v0.15.0**([설계 i093](../design/20261020-i093-xboxrecomp-v0.15.md))
  * `third_party/xboxrecomp`가 upstream v0.15.0(`6376eb8`) 위에 우리 수정을 얹은 포크 `rejsrf`(`5aae5df`)를 가리킨다. 이전 핀(v0.13.1 기반)은 포크의 `rejsrf-v0.13`에 남아 있다.
  * 이전 핀에만 있던 PR #198·#199·#200 계열과 MXCSR 수정은 v0.14.0 이후 upstream에 들어 있어 더 얹지 않는다.
* **vtable 메서드 복구**(upstream PR [sp00nznet/xboxrecomp#236](https://github.com/sp00nznet/xboxrecomp/pull/236))
  * v0.14.0의 닫힌 CFG 검사가 JSRF 메서드 103개를 버렸고, 그중 3개가 데모를 멈추게 했다. v0.15.0도 같다.
  * 빈 구간 밖의 증명된 exit(간접 꼬리, 함수인 switch arm, 따로 증명한 helper)로 닫히는 본문을 받는다. 바이트 인덱스 표는 코드로 받지 않고, 표 측정도 그 앞에서 멈춘다.
  * 113개 중 111개를 되찾는다. 남은 둘과 새로 빠진 둘은 seed로 넣었다.
* **런타임**: v0.15.0의 ABI 헤더가 요구하는 `g_eflags`(pushfd/popfd)와 `xbox_PortIn`/`xbox_PortOut`(`in`/`out`: 읽기 0, 쓰기 무시, 포트별 첫 접근 보고).
* **미해결 스텁**: 74개 → 28개. `in`·`out`·`popfd`가 미구현 명령 목록에서 사라졌다.
* 빌드하는 쪽은 `git submodule update`와 `scripts/recomp/regenerate.py`를 다시 돌려야 한다(ABI 헤더가 바뀌어 CMake가 재생성을 요구한다).

## reJSRF v0.0.43 (English)

Changes since **v0.0.42** (issue #93). **The recompilation tools move to xboxrecomp v0.15.0**, with a fix that recovers the JSRF vtable methods missed since v0.14.0, also proposed upstream.

Resolved issue: #93, the move to xboxrecomp (v0.14.0 held, now v0.15.0) and recovery of the vtable methods the table-entry check dropped; commits `1967e4c`, `b93a93d`.

Changes:
* **xboxrecomp v0.15.0** ([design i093](../design/20261020-i093-xboxrecomp-v0.15.md))
  * `third_party/xboxrecomp` points at the fork's `rejsrf` (`5aae5df`), upstream v0.15.0 (`6376eb8`) plus our fixes. The previous pin (on v0.13.1) stays on the fork's `rejsrf-v0.13`.
  * The PR #198, #199 and #200 fixes and the MXCSR fix of the old pin are upstream since v0.14.0 and are no longer carried.
* **Vtable-method recovery** (upstream PR [sp00nznet/xboxrecomp#236](https://github.com/sp00nznet/xboxrecomp/pull/236))
  * v0.14.0's closed-CFG check dropped 103 JSRF methods, three of which stopped the demo; v0.15.0 is the same.
  * A body that closes through proven exits outside its gap (indirect tails, switch arms that are functions, helpers proven on their own) is now taken. Byte index tables are never taken as code, and table measurement stops in front of them.
  * 111 of 113 are recovered; the two left and two newly displaced starts are seeded.
* **Runtime**: `g_eflags` (pushfd/popfd) and `xbox_PortIn`/`xbox_PortOut` (`in`/`out`: reads 0, writes ignored, the first access per port reported), as v0.15.0's ABI header requires.
* **Unresolved stubs**: 74 → 28. `in`, `out` and `popfd` are gone from the unimplemented list.
* Builders must run `git submodule update` and `scripts/recomp/regenerate.py` again (the ABI header changed, so CMake asks for regeneration).

Verified: xboxrecomp's upstream pytest 721 passed (the 13 new tests fail on v0.15.0 and pass with the fix). Win32 x86 Debug and Release with zero warnings; kernel probe 56, dsound probe 48, D3D8 probe 163, all with 0 failures; d3d8 check 14,018 cases and decomp check 129 cases with 0 differences; `check_hle_pops.py` 0 mismatches. Demo frames match the previous version up to the title screen; the small later difference (about a frame of character pose) comes from upstream's hardware-matched `rcp`/`rsqrt` approximation, and an exact-division experiment build was byte-identical to the previous version. User: approved the merge.
