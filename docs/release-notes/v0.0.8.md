## reJSRF v0.0.8

이전 릴리스 **v0.0.7** 이후의 변경입니다(issue #19). **커널 HLE가 I/O 완료 루틴(사용자 APC)을 전달해, 부팅이 효과 이미지 다운로드, 사운드 버퍼 생성, 첫 `D3DDevice_Swap`(첫 프레임), 폰트 읽기, 효과음 버퍼 생성까지 갑니다.** 약 50초 뒤 thread 2가 `D3DVertexBuffer_Lock` 다음에 `0x0FE80026`을 읽다 멈춥니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#19](https://github.com/nworkers/reJSRF/issues/19) | 커널 HLE 사용자 APC(I/O 완료 루틴, 경고 가능 대기) | `0166880` |

### 바뀐 것

* **사용자 APC.** 스레드별 APC 큐. `NtReadFile`, `NtWriteFile`, `NtDeviceIoControlFile`, `NtFsControlFile`, `NtQueryDirectoryFile`은 오류 없이 끝나면 `ApcRoutine`을 큐에 넣습니다. 경고 가능한 사용자 모드 대기(`NtWaitForSingleObject(Ex)`, `NtWaitForMultipleObjectsEx`, `KeWaitForSingleObject`, `KeDelayExecutionThread`)가 APC를 실행하고 `STATUS_USER_APC`를 돌려줍니다.
* **`NtUserIoApcDispatcher`**(커널 ordinal 232). XAPI `ReadFileEx`/`WriteFileEx`의 완료 루틴을 부릅니다.
* **seed.** 실행에서 닿은 vtable 슬롯 `0x0007BE30`을 `observed` seed로 넣었습니다(lift 함수 9,016개).
* **검사 도구.** `rexbox_kernel_probe`에 APC 검사 14개(모두 42개).
* **기존 체크아웃은 `regenerate.py`로 다시 생성해야 합니다.**

## reJSRF v0.0.8 (English)

Changes since **v0.0.7** (issue #19). **The kernel HLE now delivers I/O completion routines (user APCs), so boot reaches the effects image download, sound buffer creation, the first `D3DDevice_Swap` (the first frame), font loading and sound-effect buffer creation.** After about 50 s, thread 2 stops reading `0x0FE80026` after `D3DVertexBuffer_Lock`.

Resolved issue: #19, kernel HLE user APCs (I/O completion routines, alertable waits), commit `0166880`.

Changes: a per-thread user APC queue, fed by `NtReadFile`, `NtWriteFile`, `NtDeviceIoControlFile`, `NtFsControlFile` and `NtQueryDirectoryFile` when they finish without an error, and run with `STATUS_USER_APC` by alertable user-mode waits (`NtWaitForSingleObject(Ex)`, `NtWaitForMultipleObjectsEx`, `KeWaitForSingleObject`, `KeDelayExecutionThread`); `NtUserIoApcDispatcher` (kernel ordinal 232), which calls the completion routine of XAPI's `ReadFileEx`/`WriteFileEx`; the vtable slot `0x0007BE30`, reached at run time, as an `observed` seed (9,016 lifted functions); 14 APC checks in `rexbox_kernel_probe` (42 in all). **Existing checkouts need a fresh `regenerate.py`.**

Verified on Win32 x86 Debug and Release: zero build warnings, kernel probe 42/42, DSOUND probe 48/48, decomp check 6/6, d3d8 check 13,557 cases with 0 differences, 0 pop mismatches, no skipped indirect calls, stop at the `0x0FE80026` fault; CI on the pull request.
