## reJSRF v0.0.16

이전 릴리스 **v0.0.15** 이후의 변경입니다(issue #40). **오프닝 3D 데모가 Release에서 초당 8~10프레임에서 21~39프레임으로 빨라졌습니다.** 화면은 v0.0.15와 같습니다. D3D8 HLE는 바뀐 GL 상태만 보냅니다. 정점과 인덱스는 게임 메모리의 바이트가 바뀔 때만 다시 올립니다.

### 바뀐 것

* **GL 상태 캐시.** 다음은 값이 바뀔 때만 GL에 보냅니다.
  * 프로그램
  * 프로그램별 유니폼(정점 상수 `c[]`는 바뀐 구간만)
  * 텍스처와 샘플러(매개변수 조합마다 샘플러 객체 하나)
  * 깊이·블렌드·컬링·스텐실 등 고정 상태와 뷰포트
* **정점·인덱스 캐시.** 정점 버퍼 범위와 `DrawIndexedVertices`의 인덱스를 GL 버퍼에 둡니다. 게임 메모리의 바이트가 바뀌었을 때만 다시 올립니다. 업로드는 프레임당 약 3.8 MB에서 수 KiB로 줄었습니다.
* **프로그램 캐시 키.** 문자열 대신 구조체 비교와 해시를 씁니다.
* **진단.** `REXBOX_D3D8_PROFILE=<n>`은 n번째 present마다 프레임 시간이 어디에 쓰였는지 한 줄로 냅니다. 항목은 그리기 단계, present, 나머지입니다.
* **아직 남은 것.** 60프레임까지 남은 시간의 대부분은 그리기 밖에 있습니다. 게임 코드와 다른 HLE 호출이 프레임당 약 12.7 ms를 씁니다.

## reJSRF v0.0.16 (English)

Changes since **v0.0.15** (issue #40). **The opening 3D demo now runs at 21–39 frames per second in Release, up from 8–10, with the same picture as v0.0.15.** The D3D8 HLE sends only the GL state that changed. Vertices and indices are uploaded again only when their bytes in game memory change.

Resolved issue: #40, the cost of the draw path (GL state and buffer caches, frame-time measurement), commit `311f1ad`.

Changes:
* **GL state cache:** only changed values go to GL for these:
  * the program
  * per-program uniforms (for the vertex constants `c[]`, only the changed runs)
  * textures and samplers (one sampler object per parameter combination)
  * fixed state such as depth, blend, cull and stencil, and the viewport
* **Vertex and index cache:** vertex-buffer ranges and the indices of `DrawIndexedVertices` stay in GL buffers. They are uploaded again only when their bytes in game memory change. Uploads fell from about 3.8 MB to a few KiB per frame.
* **Program cache keys:** structs compared field by field with a hash, instead of strings.
* **Diagnostics:** `REXBOX_D3D8_PROFILE=<n>` prints where the frame time went every n presents: the draw phases, present and the rest.
* **Still open:** most of the time left before 60 frames per second lies outside drawing. The title's code and the other HLE calls take about 12.7 ms per frame.

Verified on Win32 x86 Debug and Release: zero build warnings; D3D8 probe 116/116, kernel probe 56/56, DSOUND probe 48/48; d3d8 check 14,018 cases with 0 differences; demo frames 2,701–3,000 (483 draws) went from 120.8 to 35.3 ms per frame; frames 2,800, 3,000, 3,200 and 3,400 are identical to v0.0.15 pixel for pixel; CI on the pull request.
