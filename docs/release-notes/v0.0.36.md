## reJSRF v0.0.36

이전 릴리스 **v0.0.35** 이후의 변경입니다(issue #82). **화면 찢어짐(tearing)이 없어졌습니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#82](https://github.com/nworkers/reJSRF/issues/82) | 화면 찢어짐: 보이는 창의 호스트 vsync, 가상 vblank 시계를 호스트 귀선에 맞춤 | `aa30f51` |

### 바뀐 것

* **호스트 vsync.** 보이는 창은 vsync로 버퍼를 교체한다. 기본은 adaptive이고, 지원하지 않으면 일반 vsync를 쓴다. `REXBOX_VSYNC=off|on|adaptive`로 고르며, 숨긴 창은 늘 끈다([설계 i082](../design/20261017-i082-vsync.md)).
* **가상 vblank 시계 위상 맞춤.** 60 Hz 근처 모니터에서 swap이 귀선을 기다리면, 가상 시계의 다음 tick이 다음 귀선보다 3 ms 앞에 오도록 맞춘다. 59.94 Hz 같은 작은 차이로 생기던 주기적인 끊김이 없다. 게임 속도는 계속 가상 시계가 정한다.

## reJSRF v0.0.36 (English)

Changes since **v0.0.35** (issue #82). **The picture no longer tears.**

Resolved issue: #82, tearing: host vsync for visible windows, with the virtual vblank clock aligned to the host's blank, commit `aa30f51`.

Changes:
* **Host vsync:** visible windows swap with vsync, adaptive by default and plain vsync where adaptive is unsupported. `REXBOX_VSYNC=off|on|adaptive` chooses it; hidden windows never wait ([design i082](../design/20261017-i082-vsync.md)).
* **Virtual vblank clock alignment:** on a monitor near 60 Hz, a swap that waited for the blank moves the virtual clock so its next tick leads the next blank by 3 ms. The periodic hitch from small rate differences such as 59.94 Hz is gone. The virtual clock still sets the game's speed.

Verified:
* Win32 x86 Debug and Release: zero build warnings; D3D8 probe 163/163; d3d8 check 14,018 cases with 0 differences; decomp check 129 cases with 0 differences.
* Behavior: hidden-window demo frame BMPs identical to v0.0.35; 60.0 fps windowed (worst 18.5 ms); no tearing in the user's play.
