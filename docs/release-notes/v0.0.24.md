## reJSRF v0.0.24

이전 릴리스 **v0.0.23** 이후의 변경입니다(issue #55). **디스어셈블러가 놓쳐 통째로 건너뛰어지던 함수 8개를 되찾았습니다. New Game 뒤 첫 대화가 끝난 다음 화면이 넘어가지 않던 문제가 고쳐졌습니다.** 이제 남은 미해결 스텁이 실행되면 그 사실을 보고합니다.

### 바뀐 것

* **함수 복구**
  * xboxrecomp fork에 늦은 tail-jump pass(`fix/late-tail-jumps`)를 더했습니다. tail-jump pass 뒤에 생긴 본문에서 빈 구간으로 가는 `jmp`의 대상을 함수(alias)로 만듭니다.
  * 7개를 되찾아 미해결 스텁이 83개에서 76개로 줄었습니다.
  * `0xA5B60`이 화면 전환에 필요한 함수입니다(사용자 시험으로 확인). `0x54750`은 데모의 매 프레임 실행됩니다.
* **간접 호출 대상**: 함수 표 `0x1EC288`의 `0x352D0`을 seed로 넣었습니다. 전에는 디스패치 항목이 없어 그 호출이 건너뛰어졌습니다.
* **보고**: 미해결 스텁이 실행되면 주소마다 한 번 알립니다(`[recomp] unresolved stub <va> called; ...`, fork `feat/stub-report`, `RECOMP_STUB_REPORT`).
* **분석**: 남은 76개를 분류했습니다([unresolved-stubs](../analysis/unresolved-stubs.md)).
  * 대부분은 alias 본문이 자기 시작 앞으로 되돌아가는 분기, 또는 데이터를 코드로 잘못 읽은 곳입니다.
* **upstream**: fork 변경 두 가지의 upstream PR은 준비만 하고 보류했습니다. 초안은 작업 로그에 있습니다.

## reJSRF v0.0.24 (English)

Changes since **v0.0.23** (issue #55). **Eight functions that the disassembler missed, and that were skipped whole, are recovered. The screen that did not move on after the first dialogue of a new game now does.** A remaining unresolved stub that runs now says so.

Resolved issue #55:
* seven tail-jump-only functions recovered and unresolved stubs report when run, commit `3f13769`
* `0x352D0`, called only from a function table, seeded, commit `6f62676`
* documents: play checks, the cause test and the end-to-end report check, commits `8431b0f`, `6f5ad0c`, `b6bbe8a`, `4ecd569`

Changes:
* **Recovered functions:**
  * A late tail-jump pass in the xboxrecomp fork (`fix/late-tail-jumps`) makes a function (alias) of the target of a `jmp` into a gap from a body made after the tail-jump pass.
  * Seven were recovered, taking the unresolved stubs from 83 to 76.
  * `0xA5B60` is needed for the screen transition (confirmed by the user's test); `0x54750` runs every demo frame.
* **Indirect-call target:** `0x352D0` in the function table `0x1EC288` is seeded; it had no dispatch entry, so its call was skipped.
* **Reporting:** an unresolved stub that runs is reported once per address (`[recomp] unresolved stub <va> called; ...`, fork `feat/stub-report`, `RECOMP_STUB_REPORT`).
* **Analysis:** the remaining 76 are classified ([unresolved-stubs](../analysis/unresolved-stubs.md)); most are alias bodies branching back before their own start, or data decoded as code.
* **Upstream:** pull requests for the two fork changes are prepared and held; drafts are in the work log.

Verified:
* Win32 x86 Debug and Release with zero build warnings
* kernel probe 56/56, D3D8 probe 116/116, DSOUND probe 48/48
* d3d8 check 14,018 cases with 0 differences; decomp check 6/6
* xboxrecomp fork: `pytest tools/recomp tools/disasm`, 541 passed
* demo: six frames identical to before
* play (user): the transition after the first dialogue of a new game works, with no `[recomp]` reports
* CI on the pull request
