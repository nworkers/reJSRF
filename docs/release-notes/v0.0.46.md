### 바뀐 것

* **빌드 선택**([20261020-i108](../design/20261020-i108-japanese-variant.md))
  * `-DREJSRF_VARIANT=jsrf_us|jsrf_jp`. 빌드 스크립트는 `-Variant jp`이고 `build\win32_x86_jp`에 빌드한다. 생성 코드는 `gen/<판>/gen`.
  * 판은 파일 이름이 아니라 내용으로 판단한다(스크립트는 MD5, 앱은 인증서). 판이 맞지 않으면 다시 빌드할 `-DREJSRF_VARIANT`를 알리고 종료 코드 1로 멈춘다.
* **공유와 확인**
  * 두 판은 같은 함수가 같은 주소에 있어 seed와 디컴파일 함수 이름을 함께 쓴다. 재생성할 때 커밋된 지문(`function_fingerprints.json`, 해시만)으로 확인한다(`variant_fingerprints.py`).
  * 판마다 다른 자료 주소는 `include/rejsrf/jsrf_addresses.h`에 둔다.
* **앱**
  * `BuiltVariant()`, `NativeLanguage()`. 일본판의 기본 언어는 Japanese이다.
  * 창 제목과 Info 탭에 `US`/`JP`를 표시한다.
* **CI**: Release 작업에서 일본판 앱을 빌드하고 스모크를 돌린다.

## reJSRF v0.0.46 (English)

Changes since **v0.0.45** (issue #108). **The Japanese XBE is supported as a build-time variant**: one executable does not run both; the US or Japanese build is chosen at CMake configure.

Resolved issue: #108, the Japanese XBE build variant; design `9894b0b`, implementation (the build told apart by content) `4e2c0f2`.

Changes:
* **Choosing the build** ([20261020-i108](../design/20261020-i108-japanese-variant.md))
  * `-DREJSRF_VARIANT=jsrf_us|jsrf_jp`; the build script takes `-Variant jp` and builds into `build\win32_x86_jp`; generated code goes to `gen/<build>/gen`.
  * The build is identified by content, never by file name (MD5 in the scripts, the certificate in the app). A mismatched XBE names the `-DREJSRF_VARIANT` to rebuild with and exits with 1.
* **Sharing and checking**
  * Both builds hold the same functions at the same addresses, so the seeds and decompiled function names are shared, checked at regeneration against committed fingerprints (`function_fingerprints.json`, hashes only; `variant_fingerprints.py`).
  * Per-build data addresses live in `include/rejsrf/jsrf_addresses.h`.
* **App**
  * `BuiltVariant()` and `NativeLanguage()`; the Japanese build defaults to Japanese.
  * The window title and the Info tab show `US`/`JP`.
* **CI**: the Release job builds the Japanese app and runs its smoke step.

Verified: the US Release build has zero warnings, passes the probes (56/48/163), `rejsrf_decomp_check` (129) and `rejsrf_d3d8_check` (14,018) with no differences, and its demo frames match the previous build. The Japanese Release build passes the same checks, and its demo equals the US build with Language=Japanese byte for byte. A mismatched build explains itself and exits with 1 both ways. User: approved the merge.
