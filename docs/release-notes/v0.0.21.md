## reJSRF v0.0.21

이전 릴리스 **v0.0.20** 이후의 변경입니다(issue #50, #44 문서 후속). **D3D8 HLE가 그리기마다 보내던 같은 GL 상태를 다시 보내지 않아, 오프닝 데모의 GL 호출이 프레임당 10,505번에서 약 4,100번으로 줄었습니다.** 화면은 같습니다.

| [#50](https://github.com/nworkers/reJSRF/issues/50) | 그리기마다의 GL 호출 줄이기, `REXBOX_GL_CALLS` 진단 | `f50aa21`, `5a636ba`(되돌림), `e149464` |
| [#44](https://github.com/nworkers/reJSRF/issues/44) 후속 | 문서: XMM intrinsic이 선택 사항임, #46·#48 frontier 행, 다음 후보 #50·#51 | `69fcdf4` |

### 바뀐 것

* **진단.** `REXBOX_GL_CALLS=1`이면 모든 GL 함수가 호출 계수 래퍼를 거치고, 프로파일 보고에 프레임당 GL 호출 수를 함수별로 냅니다.
* **GL 호출 줄이기.**
  * 정점 속성: 그리기용 VAO의 속성 상태(켜짐, 포인터)를 기억해 바뀐 것만 보냅니다. 끄기 호출이 프레임당 3,694번에서 56번으로 줄었습니다.
  * 프레임버퍼: 바뀔 때만 다시 묶습니다(그리기마다 487번 → 거의 0).
  * 정점 상수: location run마다 한 번에 보냅니다(`glUniform4fv` 861 → 160).
* **측정**(Intel HD Graphics 620): 그리기 483개 프레임의 GL 호출이 10,505 → 약 4,100번(-61%)이 됐습니다. present 스레드 CPU는 번갈아 3회 재어 약 5% 줄었습니다.
* **시도 후 되돌림.** 캐시한 정점 범위마다 VAO를 두면 호출이 2,115번까지 줄었습니다. 하지만 CPU 차이가 측정되지 않아 복잡도를 남기지 않았습니다(설계 i050 §2.4).

## reJSRF v0.0.21 (English)

Changes since **v0.0.20** (issue #50, a #44 documentation follow-up). **The D3D8 HLE no longer sends the same GL state again on every draw; the opening demo's GL calls fell from 10,505 to about 4,100 per frame.** The picture is unchanged.

Resolved issues:
* #50, fewer GL calls per draw and the `REXBOX_GL_CALLS` diagnostic: commits `f50aa21`, `5a636ba` (reverted) and `e149464`.
* #44 follow-up (docs: the XMM intrinsics are optional, frontier rows for #46 and #48, next candidates #50 and #51): commit `69fcdf4`.

Changes:
* **Diagnostics:** with `REXBOX_GL_CALLS=1` every GL entry point goes through a counting wrapper, and the profile report adds GL calls per frame by function.
* **Fewer GL calls:**
  * Vertex attributes: the draw VAO's attribute state (enable bits, pointers) is remembered and only changes are sent; disables fell from 3,694 to 56 per frame.
  * Framebuffer: bound only when it changes (487 per frame to almost none).
  * Vertex constants: one call per location run (`glUniform4fv` 861 → 160).
* **Measurement** (Intel HD Graphics 620): GL calls in a 483-draw frame went from 10,505 to about 4,100 (-61%), and presenting-thread CPU fell by about 5% in three alternating runs.
* **Tried and reverted:** a VAO per cached vertex range brought calls down to 2,115, but no CPU difference could be measured, so the added complexity was not kept (design i050 §2.4).

Verified on Win32 x86 Debug and Release: zero build warnings; kernel probe 56/56, D3D8 probe 116/116, DSOUND probe 48/48; d3d8 check 14,018 cases with 0 differences; decomp check 6/6; demo frames 2,800–3,400 with 0 pixels differing from a reference dump; CI on the pull request.
