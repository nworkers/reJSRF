## reJSRF v0.0.17 (English)

Changes since **v0.0.16** (issue #42). **The frame time of the opening 3D demo is now broken down**, with a sampling profiler and new measurement columns. The findings are in [docs/analysis/frame-time.md](../analysis/frame-time.md). Speed is the same as v0.0.16.

Resolved issue: #42, analysis of the frame time outside drawing (thread sampler, wait and cpu columns, findings), commit `adb0d03`.

Changes:
* **What a frame is made of:** a frame of the 483-draw window takes 27.9 ms.
  * 16.5 ms of CPU work on the presenting thread: lifted title code 38%, D3D8 HLE 26%, GL driver 16%
  * 10.4 ms of vblank wait
* **Diagnostics:** `REXBOX_D3D8_PROFILE` gains:
  * the vblank wait (`wait`)
  * the presenting thread's CPU time (`cpu`)
  * and it counts on the presenting thread only.
* **Sampling:** `REXBOX_SAMPLE=<first>-<last>[:<file>]` samples the drawing thread over those presents.
  * The Release link writes `rejsrf.map`.
  * `scripts/perf/resolve_samples.py` names the functions with that map.
* **Small cleanups**, neither with a measurable speed difference:
  * HLE registry lookups first check a bitmap of bound addresses.
  * Per-draw report strings are built only once.
* **Next:** improving xboxrecomp's code generation (reloads of the memory base, registers kept in memory).

Verified on Win32 x86 Debug and Release: zero build warnings; kernel probe 56/56, D3D8 probe 116/116, DSOUND probe 48/48; d3d8 check 14,018 cases with 0 differences; decomp check 6/6; the 483-draw window measures wall 27.9 ms = cpu 16.5 + wait 10.4 + about 1 ms, and the sleep share of the samples matches wait; CI on the pull request.
