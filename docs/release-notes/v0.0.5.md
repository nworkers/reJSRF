## reJSRF v0.0.5 (English)

Changes since **v0.0.4** (issue #12 follow-up). **Nine functions reached only through the driver tables of XAPI's USB device layer (XPP) are now in the recompiled code, so no indirect call is skipped during boot.** The frontier stays at kernel import 65 `IoCreateDevice` (called from `MU_Init`).

Related issue: #12 (in progress), commit `0108cd4`.

Changes: nine XPP functions added to `src/game/jsrf/recomp/seed_functions.json`; `0x001BD274` is the init function of a USB class-driver table and calls `KeInitializeTimerEx(0x002649A8)`. All are FPO functions starting right after a `ret`/`jmp` with no prologue, which the disassembler missed. **Existing checkouts need a fresh `regenerate.py`.**

Verified on Win32 x86 Debug and Release: zero build warnings, kernel probe 27/27, decomp check 6/6, d3d8 check 13,557 cases with 0 differences, no `[recomp]` warnings during boot, stop at `IoCreateDevice`; CI on the pull request.
