이전 릴리스 **v0.0.32** 이후의 변경입니다(issue #71). **부스트 대시의 블러 화면이 원본처럼 나옵니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#71](https://github.com/nworkers/reJSRF/issues/71) | 부스트 대시 블러가 원본과 다름(장면이 1/4로 축소, 나머지 회색) | `21f6845` |

### 바뀐 것

* **렌더 타깃을 표면 메모리로 식별.** 게임은 렌더 타깃 헤더 하나(`03FDBFE0`)를 프레임마다 512×512 표면과 128×128 표면에 번갈아 쓰고, 부스트 합성은 두 표면을 모두 읽는다.
  * 지금까지는 GL 텍스처·깊이 버퍼·FBO를 헤더 주소로 찾았다. 그래서 크기가 바뀔 때마다 다른 쪽 표면을 지웠고, 같은 메모리를 가리키는 옛 헤더의 낡은 사본을 읽기도 했다.
  * 이제 모두 데이터 주소(표면 메모리)로 찾는다. 같은 메모리에 크기가 다른 표면이 올 때만 다시 만든다([설계 i071](../design/20261017-i071-render-target-by-memory.md)).
* **보고.** `render target <헤더> at <메모리> (WxH)`, `texture X samples render target Y at M (WxH)`처럼 메모리를 함께 적는다.

## reJSRF v0.0.33 (English)

Changes since **v0.0.32** (issue #71). **The boost-dash blur now looks like the original.**

Resolved issue: #71, the boost-dash blur differs from the original (the scene shrunk to a quarter, the rest grey), commit `21f6845`.

Changes:
* **Render targets identified by surface memory:** the title points one render-target header (`03FDBFE0`) at a 512×512 surface or a 128×128 one depending on the frame, and the boost composite reads both.
  * GL textures, depth buffers and FBOs used to be looked up by header address, so each size change dropped the other surface, and a stale copy of an old header over the same memory could be read.
  * They are now looked up by data address (surface memory) and remade only when a surface of another size comes to the same memory ([design i071](../design/20261017-i071-render-target-by-memory.md)).
* **Reports** name the memory: `render target <header> at <memory> (WxH)`, `texture X samples render target Y at M (WxH)`.

Verified:
* Win32 x86 Debug and Release: zero build warnings; D3D8 probe 162/162; d3d8 check 14,018 cases with 0 differences; decomp check 129 cases with 0 differences.
* Behavior: demo frames 1,500, 3,000 and 4,650 are identical to before; in the user's play the boost blur looks right.
