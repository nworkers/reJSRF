이전 릴리스 **v0.0.38** 이후의 변경입니다(issue #94, #95). **게임패드 진동을 지원하고, 설정 메뉴에 Input 탭과 VBlank 대기 켜기/끄기가 생겼습니다.**

| issue | 내용 | 커밋 |

| [#95](https://github.com/nworkers/reJSRF/issues/95) | Graphics 탭의 VBlank 대기 켜기/끄기 | `f70ac63` |

보류 중인 issue: [#93](https://github.com/nworkers/reJSRF/issues/93) xboxrecomp v0.14.0 전환. v0.14.0이 JSRF의 vtable 메서드 약 113개를 놓쳐서, 다음 upstream 버전을 기다린다.

### 바뀐 것

* **게임패드 진동**([설계 i094](../design/20261018-i094-gamepad-vibration.md))
  * 게임이 `XInputSetState`로 보내는 모터 값(`XINPUT_RUMBLE`, 피드백 `+0x42`)을 SDL3 `SDL_RumbleGamepad`로 낸다. 왼쪽은 큰 모터, 오른쪽은 작은 모터다.
  * Xbox 진동은 바꿀 때까지 이어지므로, 진동 중에는 1초마다 다시 건다.
  * 설정 메뉴가 열려 있는 동안과 패드를 닫을 때는 멈춘다.
* **Input 탭**: Vibration 켜기/끄기, Strength 10~100%, Test 버튼(첫 컨트롤러 0.5초). `rejsrf.ini`의 `[Input]` 절(`Vibration`, `VibrationStrength`)에 저장한다.
* **VBlank wait**([설계 i095](../design/20261018-i095-vblank-wait.md))
  * Graphics 탭의 VSync 아래에 있고, 기본은 켬이다.
  * 끄면 가상 수직 귀선 시계가 10 kHz로 돌아 게임이 그릴 수 있는 만큼 빨리 돈다. 게임 진행이 프레임 단위라 속도도 빨라진다. 벤치마크용이고, VSync를 켜 두면 모니터 주사율에 묶인다.
  * 실행 중 바꿔도 시계 수가 이어진다. `rejsrf.ini`의 `VBlankWait`에 저장한다.

## reJSRF v0.0.39 (English)

Changes since **v0.0.38** (issues #94, #95). **Gamepad vibration, plus an Input tab and a VBlank wait on/off in the settings menu.**

Resolved issues:
* #94, gamepad vibration (`XInputSetState`) and an Input tab; commits `01bee88`, `f70ac63`.
* #95, VBlank wait on/off in the Graphics tab; commit `f70ac63`.

On hold: #93, the move to xboxrecomp v0.14.0. It misses about 113 of JSRF's vtable methods, so this waits for the next upstream release.

Changes:
* **Gamepad vibration** ([design i094](../design/20261018-i094-gamepad-vibration.md))
  * The motor speeds the game sends through `XInputSetState` (`XINPUT_RUMBLE`, feedback `+0x42`) go to SDL3's `SDL_RumbleGamepad`. Left is the large motor, right the small one.
  * An Xbox rumble lasts until changed, so a running rumble is renewed every second.
  * It stops while the settings menu is open and when the pad is closed.
* **Input tab**: Vibration on/off, Strength 10-100 %, and a Test button (the first controller, 0.5 s). Saved in `rejsrf.ini`'s `[Input]` section (`Vibration`, `VibrationStrength`).
* **VBlank wait** ([design i095](../design/20261018-i095-vblank-wait.md))
  * It sits under VSync in the Graphics tab and is on by default.
  * Off, the virtual vertical-blank clock runs at 10 kHz, so the game runs as fast as it draws. Game logic advances per frame, so the game speeds up too. It is meant for benchmarks; with VSync on, the monitor still holds it.
  * A switch while running keeps the blank count. Saved as `VBlankWait` in `rejsrf.ini`.

Verified:
* Win32 x86 Debug and Release: zero build warnings; D3D8 probe 163/163; d3d8 check 14,018 cases with 0 differences; decomp check 129 cases with 0 differences.
* Vibration: one `SDL_RumbleGamepad` takes about 0.02 ms on an Xbox Series X pad. Hidden-window demo fps with VSync and the vblank wait off matches the build before vibration (212/194/212 against 212/195/215).
* VBlank wait off: logos about 500 fps, 3D demo 180-240 fps, no stalls. Frame 1500 is the same in the off and on runs, and switching while running works.
* User: rumble seen in play (log line `rumble on port 0`). The Test button and strength are not checked yet.
