이전 릴리스 **v0.0.33** 이후의 변경입니다(issue #78). **스프레이한 그래피티가 벽에 보입니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|

### 바뀐 것

* **픽셀 셰이더 정의 상수.** 원본 `SetPixelShader`는 셰이더를 설정할 때마다 정의 안의 컴바이너 상수를 하드웨어에 올리고, `SetPixelShaderConstant`는 그 뒤에 매핑된 스테이지만 덮어쓴다.
  * 지금까지는 매핑이 있는 스테이지를 늘 런타임 레지스터에서 읽었다. 그래피티 셰이더(픽셀 셰이더 9)의 레이어 선택 상수(녹색·빨강·파랑)가 0이 되어 모든 픽셀이 알파 테스트에서 버려졌다.
  * 이제 마지막 `SetPixelShader` 뒤에 쓰인 레지스터만 런타임 값을 쓰고, 나머지는 정의의 값을 쓴다([설계 i078](../design/20261017-i078-psh-definition-constants.md)).

## reJSRF v0.0.34 (English)

Changes since **v0.0.33** (issue #78). **Sprayed graffiti now shows on walls.**

Resolved issue: #78, sprayed graffiti does not show, commit `750d78f`.

Changes:
* **Pixel shader definition constants:** the original `SetPixelShader` loads the definition's combiner constants into the hardware every time a shader is set, and `SetPixelShaderConstant` overwrites only the mapped stages afterwards.
  * Mapped stages used to be read from the runtime registers every time. The graffiti shader's (pixel shader 9) layer masks (green, red, blue) became 0, so every pixel failed the alpha test.
  * Now only the registers written since the last `SetPixelShader` take runtime values; the rest keep the definition's values ([design i078](../design/20261017-i078-psh-definition-constants.md)).

Verified:
* Win32 x86 Debug and Release: zero build warnings; D3D8 probe 163/163; d3d8 check 14,018 cases with 0 differences; decomp check 129 cases with 0 differences.
* Behavior: demo frames 1,500, 3,000 and 4,650 are identical to v0.0.33; in the user's play the sprayed graffiti shows.
