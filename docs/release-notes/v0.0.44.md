## reJSRF v0.0.44

이전 릴리스 **v0.0.43** 이후의 변경입니다(issue #104). **게임 언어를 English와 Japanese 가운데에서 고를 수 있습니다.** 설정 메뉴에 새 Game 탭을 두었습니다. 일본판 XBE를 분석해 US 빌드 하나로 일본어를 실행하는 근거를 만들었습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#104](https://github.com/nworkers/reJSRF/issues/104) | English / Japanese 언어 선택, Game 탭, US·일본판 XBE 언어 분석 | `e42a5b0`, `d235619`, `47b71c2`, `ebd51d5`, `159b850`, `fbdc876` |

### 바뀐 것

* **언어 선택**([설계 i104](../design/20261020-i104-language-option.md))
  * 게임은 빌드마다 언어 인덱스를 상수로 갖는다(US `0x1FC724` = 1 영어, 일본판 = 0 일본어). US 빌드를 올린 뒤·진입 전에 이 값을 0으로 쓰면 일본어 로고, 경고문, 타이틀과 일본어 자산이 나온다. lift는 US 하나 그대로다.
  * 설정 메뉴에 **Game 탭**을 Info 바로 다음에 두었다. `Language`(English / Japanese)는 다음 실행부터 적용되고, 실행 중 언어와 다르면 "Restart to apply."가 보인다.
  * `rejsrf.ini`의 `[Game]` 절 `Language`에 저장된다. `REJSRF_LANGUAGE=<언어>`는 그 실행에만 우선하고 저장되지 않는다.
  * 주소와 값의 뜻은 타이틀 프로파일(`jsrf_profile`)에 두고 `rexbox`는 바꾸지 않았다.
* **프랑스어·독일어·스페인어는 넣지 않았다**(설계 §3.4). 디스크의 세 언어 자산은 두 파일을 빼면 영어와 같고, 실행해도 영어 화면이 나온다. XBE 안의 번역도 그래피티 편집기와 저장 안내문뿐이며, 멀티플레이 메뉴는 `(Fr)`·`(Gr)`·`(Esp)` 자리표시자다. 한때 다섯 언어로 저장한 값은 English로 읽힌다.
* **분석**([language](../analysis/language.md)): 두 빌드가 다르게 시작하는 값은 언어 인덱스 하나뿐이고(`.data` dword 비교), US 전용으로 보였던 `0x694A0`는 배치 차이였다. 언어를 읽는 191곳 가운데 세 객체가 만들 때의 값을 저장하므로 실행 중 전환은 하지 않는다. 분석 스크립트 `data_diff.py`, `lang_reads.py`를 더했다.

## reJSRF v0.0.44 (English)

Changes since **v0.0.43** (issue #104). **The game's language can be chosen, English or Japanese**, in a new Game tab of the settings menu. An analysis of the Japanese XBE grounds running Japanese from the US build alone.

Resolved issue: #104, the English / Japanese language choice, the Game tab and the language analysis of the US and Japanese XBEs; commits `e42a5b0`, `d235619`, `47b71c2`, `ebd51d5`, `159b850`, `fbdc876`.

Changes:
* **Language choice** ([design i104](../design/20261020-i104-language-option.md))
  * Each build carries its language index as a constant (US `0x1FC724` = 1, English; the Japanese build's = 0, Japanese). Writing 0 there after loading the US build and before its entry brings the Japanese logo, warning, title and assets. The one lift stays the US one.
  * A **Game tab** in the settings menu, right after Info. `Language` (English / Japanese) applies from the next start, with "Restart to apply." while the running language differs.
  * It is saved as `Language` in `rejsrf.ini`'s `[Game]` section; `REJSRF_LANGUAGE=<language>` wins for one run and is not saved.
  * The address and values live in the title profile (`jsrf_profile`); `rexbox` is unchanged.
* **French, German and Spanish are not offered** (design §3.4). On the disc their assets equal English's apart from two files, and running them shows English screens. The XBE translates only the graffiti editor and save messages; the multiplayer menus are `(Fr)`/`(Gr)`/`(Esp)` placeholders. Values saved while there were five languages read as English.
* **Analysis** ([language](../analysis/language.md)): the language index is the only value the two builds start with differently (a `.data` dword diff), and `0x694A0`, which looked US-only, is a placement difference. Of the 191 reads, three objects keep the value they were created with, so the language does not switch while running. New analysis scripts `data_diff.py` and `lang_reads.py`.

Verified: Win32 x86 Release with zero warnings; kernel probe 56, dsound probe 48, D3D8 probe 163, all with 0 failures; d3d8 check 14,018 cases and decomp check 129 cases with 0 differences. English (default): the 168 file opens and the demo frames equal the build before the setting. Japanese: opens `LogoJ`, `Title.dat`, `se_ppl_j` and `SprNorm`, and the logo, warning and title come out as in the Japanese build, with no new warnings or errors. Settings: a value changed in the Game tab is saved to `rejsrf.ini` (the user's run); unknown values and `REJSRF_LANGUAGE` behave as designed. User: approved the merge; the Japanese menus past Press Start have not been seen on screen yet.
