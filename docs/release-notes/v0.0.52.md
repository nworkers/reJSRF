### 바뀐 것

* **빌드 진입점**([설계 i119](../design/20261025-i119-linux.md)): `CMakePresets.json`의 `linux-{x64,x86}-{debug,release}[-jp]`(Ninja, x86은 `-m32`; Linux 호스트에서만 보임)와 `scripts/build_linux.sh <arch> <config> [us|jp] [--no-test] [--target …]`. 결과는 `build/<preset>/`.
* **재생성**: `regenerate.py`가 `rexbox_xdk_symbols`를 자기 호스트의 빌드에서만 찾는다. WSL에서는 Windows 빌드 폴더도 보여 Windows `.exe`를 집었고, 그 프로그램이 `/mnt/…` 경로를 열지 못해 실패하던 문제다.
* **CI**: `linux` 작업(x64·x86 × debug·release). 생성 코드 없는 빌드, rexbox probe(ctest), 앱 smoke, x64 release에서 일본판 앱 빌드.
* **rexbox**: [v0.0.13](https://github.com/reexec/rexbox/releases/tag/v0.0.13)(Linux GCC 경고 2개, 그중 DPC trace 문자열 마지막 글자 잘림은 실제 버그)과 [v0.0.14](https://github.com/reexec/rexbox/releases/tag/v0.0.14)(생성 코드 없는 트리에서 GNU ld가 레지스터 접근 함수 대체 라이브러리를 링크 줄에서 그 사용자보다 앞에 두어 앱이 링크되지 않던 문제; 이 작업의 첫 CI가 잡음).
* **문서**: 가이드 [linux-setup-and-build.md](../guides/linux-setup-and-build.md)(패키지, capstone 가상 환경, 재생성, 빌드, 실행, WSL의 GPU `GALLIUM_DRIVER=d3d12`), `README.md` 플랫폼 상태, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md`.
* **태그 릴리스**(사용자 요청): `.github/workflows/release.yml`. `v*` 태그를 push하면 태그가 `VERSION`과 같고 `main` 위에 있는지 확인한 뒤 모든 호스트에서 CI와 같은 빌드·probe를 하고, `docs/release-notes/<tag>.md`가 있으면 그 본문으로 GitHub Release를 만든다(소스만). `AGENTS.md`에 규칙을 더했다. 이 버전의 태그가 첫 실행이다.
* 빌드하는 쪽은 `git submodule update --init --recursive`가 필요하다.

## reJSRF v0.0.52 (English)

Changes since **v0.0.51** (issue #119). **reJSRF builds and runs on Linux x64 and x86 (-m32).** The code is Win32's; the platform layer is rexbox's Linux implementation. Checked on WSL2 Ubuntu 24.04 with GCC 13.

Resolved issue: #119, the Linux app; commits `3f6903a` (design), `a3f20f4` (presets, build script, CI, regeneration on Linux, guide), `6edca4f` (rexbox v0.0.14), `ed65431` (the Japanese regeneration comparison).

Changes:
* **Build entry** ([design i119](../design/20261025-i119-linux.md)): the `linux-{x64,x86}-{debug,release}[-jp]` presets of `CMakePresets.json` (Ninja; `-m32` for x86; Linux hosts only) and `scripts/build_linux.sh <arch> <config> [us|jp] [--no-test] [--target …]`, building into `build/<preset>/`.
* **Regeneration**: `regenerate.py` looks for `rexbox_xdk_symbols` in this host's builds only. On WSL the Windows build folder is visible too, so the Windows `.exe` was picked and, unable to open `/mnt/…` paths, failed.
* **CI**: a `linux` job (x64 and x86 × debug and release): the build without generated code, rexbox's probes (ctest), the app smoke checks, and the Japanese app build on x64 release.
* **rexbox**: [v0.0.13](https://github.com/reexec/rexbox/releases/tag/v0.0.13) (two Linux GCC warnings, one a real truncation of the DPC trace string) and [v0.0.14](https://github.com/reexec/rexbox/releases/tag/v0.0.14) (in a tree without generated code GNU ld placed the accessor stand-in archive before its user, so the application did not link; found by this task's first CI run).
* **Documents**: the guide [linux-setup-and-build.md](../guides/linux-setup-and-build.md) (packages, a capstone virtual environment, regeneration, build, running, the GPU in WSL through `GALLIUM_DRIVER=d3d12`), `README.md` platform status, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md`.
* **Tag releases** (user request): `.github/workflows/release.yml`. A pushed `v*` tag must equal `VERSION` and sit on `main`; the CI build and probes then run on every host, and when `docs/release-notes/<tag>.md` exists a GitHub Release is created with it as the body (source only). `AGENTS.md` gains the rule. This version's tag is its first run.
* Builders need `git submodule update --init --recursive`.

Verified: Linux x64 and x86 × Debug and Release plus the x64 Release Japanese build, all with 0 warnings and ctest 4/4, and x64 Debug without generated code links (rexbox v0.0.14); `rejsrf_decomp_check` 129 and `rejsrf_d3d8_check` 14,018 with 0 differences on Linux x64 Release; regeneration on Linux (capstone 5.0.7) gives, for both builds, 42 of 43 files equal to Windows' apart from line endings and one differing only in a generator-name comment; every build's demo file-open sequence equals the Windows baseline, with frames byte-identical between x64 and x86 and differing from Windows only by renderer rounding; a visible WSLg window renders on the GPU (D3D12/RTX 4090), opens an audio device, takes keyboard input (title to main menu) and loads the Korean folder; Windows is unaffected (0 warnings, probes 94/55/220, decomp check 129 with 0 differences); CI: the Win32 Debug and Release jobs and the four Linux jobs pass. User: approved the merge.
