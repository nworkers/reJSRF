## reJSRF v0.0.32

이전 릴리스 **v0.0.31** 이후의 변경입니다(issue #75). **HLE 호출마다 드는 고정 비용을 줄여, 데모 구간에서 HLE 경로가 차지하는 CPU 비중이 절반으로 줄었습니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#75](https://github.com/nworkers/reJSRF/issues/75) | HLE 호출마다 드는 고정 비용 줄이기 | `1d3f22e` |

### 바뀐 것

* **시각 기록.** 정지 보고용 HLE 진입 기록이 호출마다 `QueryPerformanceCounter`를 읽지 않는다. 정지 감시 스레드가 0.1초마다 갱신하는 시계를 쓴다. 정지 판단은 지금처럼 1초마다다.
* **인자 읽기.** `HleCall`이 esp를 생성할 때 한 번만 읽는다.
* **레지스터 접근.** `rexbox_recomp_get/set_gpr`이 레지스터를 직접 읽고 쓴다.
* **효과.** 데모 구간(프레임 2,700~3,300)에서 HLE 경로가 대기를 뺀 CPU에서 차지하는 비중이 9.1%에서 4.5%가 됐다.

## reJSRF v0.0.32 (English)

Changes since **v0.0.31** (issue #75). **The fixed cost of every HLE call is trimmed, halving the HLE path's share of CPU in the demo window.**

Resolved issue: #75, trim the fixed cost of every HLE call, commit `1d3f22e`.

Changes:
* **Time stamps:** the HLE entry note for the stall report no longer reads `QueryPerformanceCounter` on every call. It uses a clock the stall monitor refreshes every 0.1 s; the stall check stays once a second.
* **Arguments:** `HleCall` reads esp once, when it is made.
* **Registers:** `rexbox_recomp_get/set_gpr` read and write the register directly.
* **Effect:** over demo frames 2,700–3,300 the HLE path's share of non-wait CPU fell from 9.1% to 4.5%.

Verified:
* Win32 x86 Debug and Release: zero build warnings.
  * Probes: kernel 56/56, D3D8 162/162, DSOUND 48/48.
  * d3d8 check: 14,018 cases with 0 differences. decomp check: 129 cases with 0 differences. HLE pop check: 0 mismatches.
* Behavior: a provoked 3-second stall is reported correctly (the last HLE call and its age), and so is the resumption.
* CI on the pull request.
