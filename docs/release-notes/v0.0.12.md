## reJSRF v0.0.12

이전 릴리스 **v0.0.11** 이후의 변경입니다(issue #29). **스테이지 로드가 게스트 메모리 부족 없이 끝나고, 3D 어트랙트 데모(도시 비행과 거리)와 음악이 나옵니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#29](https://github.com/nworkers/reJSRF/issues/29) | 스테이지 로드 중 게스트 메모리 부족(평면 64 MiB가 예약한 페이지를 모두 차지) | `cdb4afe` |

### 바뀐 것

* **게스트 주소 공간 128 MiB.** 아래 64 MiB는 물리 RAM(연속 메모리, 풀, HLE 객체)이고, 위 64 MiB는 `NtAllocateVirtualMemory`만 씁니다.
* **작은 할당.** base 0인 64 KiB 미만 예약은 페이지 정렬합니다. 작은 HLE 객체와 풀 블록은 크기 등급 slab에서 나옵니다.
* **D3D8.** 그리기와 텍스처 캐시의 주소 마스크가 위 64 MiB의 주소를 지킵니다(`0x07FFFFFF`).
* **진단.** 메모리 부족 trace에 남은 바이트와 가장 긴 연속 구간을 적습니다.

### 확인한 것

|---|---|

| 부팅 | 150초 동안 메모리 부족 없이 로고 → 3D 어트랙트 데모, 음악 재생 |

## reJSRF v0.0.12 (English)

Changes since **v0.0.11** (issue #29). **The stage load completes without running out of guest memory, and the 3D attract demo (a flight over the city, then the streets) plays with music.**

Resolved issue: #29, guest memory running out while loading the stage (the flat 64 MiB backed every reserved page), commit `cdb4afe`.

Changes:

* **A 128 MiB guest address space.** The low 64 MiB is physical RAM (contiguous memory, pool, HLE objects); the upper 64 MiB serves only `NtAllocateVirtualMemory`.
* **Small allocations.** Base-0 reservations under 64 KiB are page aligned. Small HLE objects and pool blocks come from size-class slabs.
* **D3D8.** The address masks in drawing and the texture cache keep addresses in the upper 64 MiB (`0x07FFFFFF`).
* **Diagnostics.** The out-of-memory trace reports the free bytes and the longest free run.

Verified on Win32 x86 Debug and Release:

* Zero build warnings.
* Probes 56/56, 48/48 and 81/81.
* decomp check 6/6.
* d3d8 check 14,018 cases with 0 differences.
* 0 pop mismatches.
* Boot: 150 s from the logos into the 3D attract demo with music, no memory exhaustion.
