## reJSRF v0.0.53 (English)

Changes since **v0.0.52** (issue #121). **The build scripts catch a submodule that is not checked out before CMake runs and name `git submodule update --init --recursive`.** rexbox (`third_party/rexbox`) carries its own submodules (SDL, imgui, smaa, XbSymbolDatabase), so after a plain `git submodule update --init` those four directories were empty and the configure stopped inside rexbox with a message naming the same non-recursive command.

Resolved issue: #121, the nested-submodule check in the build scripts; commits `4fc01c5` (the scripts) and `4a7569d` (rexbox v0.0.15).

Changes:
* **Build scripts** ([work log i121](../work-logs/20261025-i121-nested-submodule-check.md)): `scripts/build_win32_x86.ps1` and `scripts/build_linux.sh` read `git submodule status --recursive` before configuring; when a submodule is not checked out (a line starting with `-`) they name its path and `git submodule update --init --recursive` and stop. A tree without `.git` (an exported source) skips the check. No nested submodule is named.
* **rexbox**: [v0.0.15](https://github.com/reexec/rexbox/releases/tag/v0.0.15) (reexec/rexbox#33): the four submodule-missing messages in its CMakeLists.txt and the Win32 guide name the recursive command. No code change.
* Builders need `git submodule update --init --recursive`. No regeneration is needed.

Verified: with `third_party/rexbox/third_party/smaa` deinit-ed, the `.ps1` stops before CMake with `Submodule(s) not checked out: third_party/rexbox/third_party/smaa; run: git submodule update --init --recursive` (exit code 1) and the `.sh` with the same advice (exit code 2); with everything checked out the full Win32 x86 Release build passes the check and builds through `rejsrf.exe` with 0 warnings; the configure with rexbox v0.0.15 prints `rexbox version 0.0.15` with no error. User: approved the merge.
